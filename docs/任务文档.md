## 1. 解码与探测

认领顺序保持：平台 MediaCodec，然后 NextLib FFmpeg，然后 MJPEG，最后 WMV2 / 专用 ASP 的 legacy。`OwnedSurfaceCloner` 不要拆。它存在的理由是软解不要把 CPU 连接留在播放器 Surface 上，否则下一条硬解 `configure` 报 `already connected`。

### A1　WMV2 / ASP 的 AVI 在正片上不成立　P0

这条软解通路目前只在「有 idx1 的短片、无 B 帧、MP3 音频」上成立。四条边界各自能让一部正片失效。

**32MB 上限套在 LIST 上。** `Wmv2AviExtractor` 的 `MAX_CHUNK = 32L * 1024 * 1024`。读头时先做 `if (size > MAX_CHUNK) throw`，然后才进入 `"movi"` 分支。AVI 的 `movi` 是 LIST，size 等于 4 加上整段媒体数据。正片几乎都超过 32MB，在这里抛 `IOException`。探测侧 catch 之后得到 0 条 format，判 `Unplayable`。播放侧被映射成 `ERROR_CODE_PARSING_CONTAINER_MALFORMED`，文案是「封装格式暂无解封装支持」。OpenDML 把 size 写成 `0xFFFFFFFF` 的超过 2GB 文件，同一行出局。

改法：`MAX_CHUNK` 只约束叶子 chunk（`strf`、`idx1`、样本）。`LIST` 只读头，不按 size 拒绝。`moviEnd` 用文件总长夹住。OpenDML 的超级索引可以后做，但不要再让 `0xFFFFFFFF` 直接抛。

**没有 idx1 时的扫描。** `buildByScan` 每读到一个 chunk 就 `return RESULT_SEEK`，把本来顺序的扫描做成跳跃。探测侧每次 SEEK 都 `dataSource.close()` 再 `open()`。`content://` 上就是反复 `openAssetFileDescriptor`。两小时 25fps 大约十几万到二十万个 chunk。

比较「这条流是否见过」用的是 `scanned.none { }`，并且每个 chunk 分配一个 String 形式的 ckid。长文件是 O(n²) 次比较加同样次数的分配，起播可以卡到 ANR。

`FormatProbe` 的 `MAX_READS = 400`。扫描阶段一轮 read 还走不到 `format()`，400 轮用完就退出，samples 仍空，判 `unknownVideoCodec`。能播的文件被写成「没有受支持的视频编码」，而且下面会进缓存。

`SeekMap.isSeekable()` 返回 true，但关键帧启发式把该流的第一个样本当成唯一关键帧。`getSeekPoints` 对任何目标时间都回到第 0 帧。用户拖动进度条之后从头播，没有错误提示。

`samples` 全量驻留。十八万个对象大约数 MB 到几十 MB，`seek()` 用 `indexOfFirst` 做 O(n)。拖动时播放线程上反复线性扫。

改法，同一批：

1. 扫描用 `skip` / `readFully` 在同一次 read 里向前走。只有真正的随机跳转才 `RESULT_SEEK`。
2. ckid 改成 Int（fourcc 位拼）。用布尔数组或 `MutableSet<Int>` 记录流是否出现过，去掉 `none { }`。
3. `materialize` 之后清空中间列表 `scanned`。样本索引用平行的 `IntArray` / `LongArray`，seek 用二分。非关键帧用 `strh` 的 `dwScale/dwRate` 推时间，不要为每个 chunk 留一个对象。
4. 没有可靠关键帧信息时 `isSeekable()` 返回 false。不要谎报可拖。识别 I 帧（WMV2 帧类型位、MPEG-4 VOP 的 `vop_coding_type`）可以后做。
5. 探测侧：`reads >= MAX_READS && !tracksEnded`，或者 read 抛了异常，返回 `Result.Unknown`，不写入缓存。类注释已经承诺「拿不准放行」，代码要跟上。

**时间戳。** 样本时间是「该流上的序号 × scale/rate」，序号按文件顺序递增。idx1 的顺序是解码顺序。Xvid 开了 B 帧时，解码顺序不是显示顺序。`legacy_decoder.c` 里 `pkt->pts = pkt->dts = pts_us`，解码器失去重排依据，`best_effort_timestamp` 也没有可用的重排信息。VBR MP3 每帧样本数不恒定，按条数打戳会漂到秒级。`dwRate == 0` 时 `coerceAtLeast(1)` 会把每条索引当成 1 秒。

改法：视频包的 pts 用显示时间或让解码器重排，`dts` 不要抄成 pts。音频至少解析 MP3 帧头。这项要有带 B 帧的样本才能验收，和 A1 的扫描修复分开测。

**读样本的分配。** `readSample` 每个样本 `ByteArray(size)` 再包一层 `ParsableByteArray`。25fps × 100KB 是每秒数 MB 的短命对象。送进解码器时 `LegacyVideoRenderer` 再 `ByteArray(data.remaining())`，JNI 侧 `av_new_packet` 又拷一次。`DecoderInputBuffer` 本来就是 direct。

改法：按 `maxInputSize` 复用一块 scratch。`nativeSend` 改为接收 `ByteBuffer`，用 `GetDirectBufferAddress`。`av_packet` 的 padding 用一块预分配缓冲，不要每包 malloc。

> 落地订正（2026-10-15，E139）：**改法 1 与 2 的一半在 media3 1.11 的公开 API 上做不到，别再按原文施工**——`ExtractorInput` 没有 `skip`/`seek`（`seek(PositionHolder,long)` 只在 `DefaultExtractorInput` 实现类上），`DataSource` 接口只有 `addTransferListener/open/getUri/read/close`，`seek`/`canSeekAt` 在 `BaseDataSource` 上而工厂返回的是 `DataSource`（两条都是编译失败试出来的）。于是"同一次 read 里向前走"落不了地（不返回 SEEK 就得把 payload 真读出来丢，两小时正片是几 GB 白读），**"每块一次 SEEK → `content://` 上一次 `openAssetFileDescriptor`"这条风暴原样还在**。要断它得给探测换一个可随机访问的输入（先落成 fd / 缓存副本再走 `FileDescriptorDataSource`）——新记一条，仍归本条。**已落地的**：`LIST` 不再被 `MAX_CHUNK` 拒（上限只留给 `hdrl` payload / `idx1` / 样本，其余夹到文件长度，OpenDML 的 `0xFFFFFFFF` 一并夹住）；`ckid` 改 fourcc 打包 Int、"见过没有"改集合（去掉 O(n²) 与每块一个 String）；`materialize` 后清 `scanned`；截断/跑偏改为**用已有部分收尾**而不是抛出去让整片出局；`seek()` 偏移单调时二分；`isSeekable()` 只在 idx1 给真关键帧位时才 true（**无 idx1 的文件现在拖不动，这是本条改法 4 要的口径、不是回归**）；`FormatProbe` 预算耗尽或读取抛异常且零格式时返回 `Unknown`（配合既有"Unknown 不缓存"，能播的文件不再被永久记成"编码不支持"）。判定在 `AviChunkTest` 6 项（构造"声明 4GB 的 movi"只要 12 字节，不受 B17 素材限制）。**仍未动**：时间戳 / `pts = dts`（要带 B 帧与 VBR MP3 的样本）、`samples` 换平铺数组、`readSample` 的 scratch 与 `nativeSend` 收 `ByteBuffer`、OpenDML 超级索引、I 帧识别。**真机 0 证据**（B17）。
>
> **回归与修复（10-16，E141）**：本半修在真机上把 WMV2 **打回过一次**——解封装器「未知 LIST」分支多算一个 `size`（写成 `size + (size - 4)`），seek 越过 `movi`，`formats=0`、判词是"没有受支持的视频编码"。用 A/B 实验坐实归属：把 A1 动的两个文件临时退回 `a2ee312^`（`git checkout`）重出包，预 A1 判词 `formats=1 mimes=[video/x-np-wmv2]`、A1 后 `formats=0`——**是这条引入的，不是设备/格式问题**。修法把这段算术提成纯函数 `AviChunk.nextAfterUnknownList(positionAfterType, size)` 并补单测（奇偶各一例），解封装器改调它，复验 `formats=1` + 视频真播。**教训**：A1 当时只有 JVM 单测，而 `AviChunk` 那几个纯函数并没有覆盖"解封装器**怎么调**它们"——这次是"先量后改"这条纪律把自家 P0 抓回来的。

### A17　探测两头都偏　P1

**该拒的放行了。** `FormatProbe.hasPlatformDecoder`：mime 查不到就 `return true`；`MediaCodecList` 查询抛异常就 `getOrDefault(true)`。`findDecoderForFormat` 不看 MPEG-4 profile。`Mp4vAspGate` 只在设备列表里明确没有 ASP 时才改专用 mime。设备自称支持 ASP，或列表为空，就留下 `video/mp4v-es`。FFmpeg 表和 `LegacyVideoRenderer` 都不认这个 mime。探测说可播，真机 `configure` 失败，没有软解退路。

**拿不准的被定罪并记住。** 预算耗尽、一次 `read()` 抛异常、sniff 抛异常，都落到 `Unplayable` 或「文件已损坏」。缓存条件是 `sizeBytes > 0` 且结果不是 `Unknown`，于是瞬态 I/O（存储暂时不可用、SAF 刚失效）也会被记住。重试的语义是「文件没变，再看一次」，第二次 0ms 命中同一条结论。缓存没有 invalidate。重试还把起点设成 0，断点丢掉。

改法：

- 查询异常改为 false，不要 true。
- `quarterSample` 或 VOS 已是 ASP 时，即使用户设备广告了 ASP，也走专用 mime。本进程里已经 `DECODER_INIT_FAILED` 的指纹，下次强制改写。
- 只缓存确定性结论：`Playable`、`containerUnsupported`、`videoCodecUnsupported`。`Unknown` 和 `unreadable` 不进缓存。
- `FormatProbe` 增加 `invalidate(uri)` 或 `probe(bypassCache = true)`。错误面板的重试走 bypass，起点用 `history.positionOfIfIntact`。
- 现有「clip 走平台、qpel 走 nplegacy」的测试必须还在。

`Mp4vAspGate` 比的是全部 mp4v 解码器 profile 的并集。平台软解几乎总会声明 ASP，于是 `requiresDedicatedDecoder` 恒为 false，流保持 `video/mp4v-es`。真正被 `findDecoderForFormat` 选中的硬解却可能只有 Simple，第一帧 `OMX_ErrorUnsupportedProfile`。

改法：先 `findDecoderForFormat` 拿到将要使用的那一个解码器，再读它的 `profileLevels`。并集只在没有任何命中时当兜底。

ASP 改写只包了 `com.homesoft.exo.extractor.avi.AviExtractor`。同一条 qpel 码流，AVI 能进 `libnplegacy`，MP4/MKV 仍是 `video/mp4v-es`，探测对所有容器都可能判不可播。包装层同时包上 `Mp4Extractor` 和 `MatroskaExtractor`，或者把「`video/mp4v-es` 且选中的解码器没有 ASP」的认领下移到 `LegacyVideoRenderer`，不改 mime。

profile 求交目前只有 mp4v。AVC High 10、HEVC Main 10、VP9 Profile 2、AV1 高位深仍按 mime 加尺寸放行，运行期才崩。这是下一轮，和上面的「问选中的那个解码器」用同一套求交，不必和 A1 绑在一起。`PlaybackFailure.videoProfileUnsupported` 的文案已经能承接。

有视频轨时完全不查音频解码器。`hasPlatformAudioDecoder` 只在纯音频分支用。H.264 + DTS/TrueHD/WMA 会被判 `Playable`，起播后无声或在音频渲染器上失败。视频分支对音频同样求平台解码器或 FFmpeg 是否支持。不支持时在 `Playable` 上带 `audioUnsupported`，UI 提示「视频可解、音轨不可解」，不要静默。

> 承接与边界（2026-10-15 合并）：旧档挂在性能账里的那条「`mp4v-es` 探测判可播、装载后 `MediaCodecVideoRenderer` 报错」**就是本条的 profile 求交问题**，不再单独记账。`2f1c89e` 落地的 `FormatProbeDecisionTest` 插桩只证探测决策（双模拟器各 3 项：MJPEG 可播 + 软解提示、WMV2 不可播、Xvid 基线可播），native-load 那半没跑过——不能拿来给本条背书。

### A10　兼容档不要全局软解优先　P1

`PlaybackService` 在 `hardwareDecodePreferred == false` 时把工厂设成 `EXTENSION_RENDERER_MODE_PREFER`，否则是 `ON`。Media3 的 `DefaultRenderersFactory` 在 `PREFER` 时把扩展渲染器插到平台 `MediaCodecVideoRenderer` 之前。设置若承诺的是「旧格式更兼容」，实现是「H.264、HEVC、VP9、AV1 有硬解也先软解」。

NextLib 覆写了 `buildVideoRenderers`，这一层是否原样保留 `PREFER` 的插入顺序，要在改渲染器顺序之前对 `NextRenderersFactory` 确认一次。确认之后再改，不要带着疑问把顺序反转两次。

改法是按轨分流，不是一个全局 PREFER：

- 平台 `MediaCodecList` 明确支持、且不是已知坏 profile：仍硬解优先。
- 平台不支持，或 `FormatProbe` 标了 `softwareVideoOnly`：才允许 FFmpeg / MJPEG / legacy 排到前面。

`FormatProbe` 的「有没有解码器」必须用同一套规则。开关继续在下一次播放器实例生效。要立即生效就单独重建会话并保留位置，不要和分流混做。

### A18　硬解认领失败后，后面的渲染器接不住　P1

`setEnableDecoderFallback(true)` 只在同一个 `MediaCodecVideoRenderer` 里换下一个平台 codec。平台已经 `FORMAT_HANDLED` 但 `configure` 失败（10bit、Surface 仍被占用、mp4v profile）时，不会改选后面的 FFmpeg 或 Legacy。兼容档反过来：软解失败也不会回到硬解。

在 `onPlayerError` 里对 `DECODER_INIT_FAILED` / `EXCEEDS_CAPABILITIES` 只重试一次。记下失败的 mime 和 codec 名，用 `MediaCodecSelector` 排除它，或对这条 mp4v 走专用 mime，然后重新 `prepare` 同一条。不要无限重试。音频轨的解码错误不要映射成 `videoCodecUnsupported`。`terminalFailure` 留下，否则 Idle 会把错误面板冲掉。

### A11　WMV2 有画无声，VC-1 没有解码器　P1

`Wmv2AviExtractor` 的音频 tag 只把 `0x0055` / `0x0050` 映射成 `audio/mpeg`，其它返回 null。`materialize` 只保留 WMV2 视频和 `audioMime != null` 的流。Windows 上常见的 PCM（`0x0001`）和 WMA（`0x0161` / `0x0162` / `0x0163`）被丢掉。这个提取器在 `NpExtractorsFactory` 里排第一，sniff 命中后独占文件，其它流不会落到 Media3 的 AVI 提取器。探测因为有视频轨就判可播。用户看到有画面、永远没声音，排障面板也没有原因。

短期：补上 PCM 和 WMA 的 tag。平台解不了的 WMA 不要丢轨，改成「音轨不可解」的明确结果。`blockAlign` 填到 `maxInputSize`。

中期：`libnplegacy` 的解码器表现在只有 `wmv2,mpeg4`。显示名已经有「WMV (VC-1)」，解码器没有。VC-1 / WMV3 / WMV1 在绝大多数机器上直接 `videoCodecUnsupported`。若要补，在静态链入里加对应解码器，并同步 `LegacyDecoderLibrary` 和 `FormatProbe`。这一步涉及 `build-ffmpeg.sh` 和 ABI 体积，单独排，不要和「如实报音轨不可解」绑死。

RealMedia（`.rm` / `.rmvb`）、ASF 容器、MS-MPEG-4 v2/v3（`msmpeg4v2` / `msmpeg4v3`）同样是名字有或容器可读、解码器没有。`.wmv` 若不是本提取器能认的 AVI，会落进没有 ASF demux 的路径。这些是能力缺口，不是这一轮的正确性修复。PGS 保持不支持，不要自写位图字幕解码器。

### A19　legacy 软解的速度和颜色　P1

自编译 FFmpeg 在 `build-ffmpeg.sh` 里打开了 `--disable-asm`、`--disable-inline-asm`、`--disable-runtime-cpudetect`，并叠加 `--enable-small`。mpeg4 / wmv2 在 aarch64 上的 IDCT、put_pixels、h263dsp 汇编因此不进库。关汇编与 LGPL 无关，FFmpeg 自己的汇编在 `--disable-gpl` 下仍是 LGPL。`legacy_decoder.c` 又把 `thread_count` 设为 1。

这和 NextLib 那条 FFmpeg 渲染器是相反的问题。NextLib 用 `availableProcessors()` 做线程数，应用侧没有封顶，8 核上软解 HEVC 会占满大核。两处不要用同一个数：

- legacy：`thread_count` 改为 `min(4, 在线核数)`，`thread_type` 用 slice；若帧线程引入的延迟让 `pump()` 对不齐，再退回 slice only。
- NextLib：自行插入渲染器时封在 `min(4, max(2, 核数 / 2))`，1080p 以下可以用 2。不要为了封顶打开 `DecoderManager`。

色彩。`enqueue_frame` 里名为 colorspace 的字段只存了 full / limited 一个 bit。`nativeRender` 的系数恒为 BT.601 limited（`298 * c + 409 * e` 那一组）。HD（宽或高 ≥ 720）规范是 BT.709，用 601 会发灰、肤色偏。`AVFrame` 的 `colorspace`、`color_range`、`color_trc` 都没读。

改法：把 matrix 和 range 分开带出（`nativePeek` 的数组加长，Kotlin 侧 `LegacyCodec` 一起改）。`nativeRender` 按矩阵选系数。取不到时，`width >= 1280 || height >= 720` 用 BT.709，否则 BT.601。

缩放。`--disable-swscale` 之后，`nativeRender` 对每个输出像素做两次 64 位除法，再逐像素 `yuv_to_rgb`。1080p 全屏是每帧两百万次迭代的标量最近邻，非 1:1 时有锯齿。另外每帧都 `ANativeWindow_fromSurface`、`setBuffersGeometry`、`lock`、`unlockAndPost`、`release`。

三选一，只做一条：

1. 重新 `--enable-swscale`，`sws_scale` 输出到窗口缓冲。体积大约增加几百 KB，换 NEON 和双线性。
2. 不引 swscale：预计算 `dx → sx` 和每行的 `sy`，1:1 时走无缩放分支，RGBA 按 32 位写。
3. `setBuffersGeometry` 请求与视频原始尺寸一致，缩放交给 GPU，native 只做 1:1。

窗口句柄按 Surface 缓存，几何只在宽高或格式变化时设置。不要三条路径一起换。

拷贝与队列。一帧的路径是：AVFrame → native `malloc` + memcpy → `nativeCopy` 到 Java direct buffer → `copyPlane` 进 `VideoDecoderOutputBuffer` → `nativeRender` 写 RGBA。`LegacyCodec.receive()` 每帧 `ByteBuffer.allocateDirect` 三次。`MAX_QUEUE = 16`，满了返回 `ENOMEM`，`drain()` 把整条播放打成终态，而不是背压。1080p 队列加输出缓冲的峰值可以到一百 MB 量级。`avcodec_send_packet` 返回 `EAGAIN` 时直接失败，没有先 drain 再送。`AVERROR_INVALIDDATA` 也上抛成终态，截断的 AVI 帧会把整部片子打死。`nativeCopy` 校验失败时返回 void，帧不弹出，队列永久满，画面是黑或绿。

改法：

- direct buffer 和 native 平面按最大帧尺寸分配一次，尺寸不变就复用。
- `MAX_QUEUE` 降到 3 或 4。满时停止送包，等消费，不要当解码失败。
- `EAGAIN`：先 drain，再重试一次 send。`INVALIDDATA`：丢这一帧并计数，不抛 `DecoderException`。
- `nativeCopy` 改返回布尔。失败上抛，不要构造全零帧。
- 非 YUV420P / YUVJ420P 的帧跳过并记日志，不要终止播放。
- `send` / `receive` 挪到解码线程。`queueInputBuffer` 只入队。早于 `outputStartTimeUs` 的包不要收成整帧。输出池固定数量，满了丢帧，不要 `new`。
- 能让 native 从 AVFrame 直接画上 Surface，就去掉中间的 Java 平面。这一步和上面的缓冲复用分两轮，先做复用。

`OwnedSurfaceCloner` 克隆失败时现在 `return surface`，于是重新引入它要修的 `already connected`，生产环境只有一条 DEBUG 日志。失败仍退回原 Surface，播放不要因此停，但必须 `Log.w` 一次，并记一条用户可见的诊断（`ProbeMemo` 一类）。

> 复核订正（2026-10-15）：原文另有两句要求——`release()` 要幂等、Surface 在未 disable 被换掉（旋转、分屏）时要在设置新 Surface 时释放旧克隆——现码已满足（`OwnedSurfaceCloner.kt:30-31`、`:38-42`），已移进 §10 的「不要再当缺陷报」，本条只剩 `Log.w` 与用户可见诊断这一半。

FFmpeg 软解没有走这套 cloner。`OwnedSurfaceCloner` 只包了 `LegacyVideoRenderer` 和 `NpMjpegVideoRenderer`。NextLib 的 `FfmpegVideoDecoder.renderToSurface` 把播放器 Surface 直接交给 native lock。FFmpeg 软解（MPEG-2、部分 HEVC）之后切回硬解，仍可能 `already connected`。子类化 `FfmpegVideoRenderer`，`renderOutputBufferToSurface` 走同一套 cloner，`onDisabled` / `onRelease` 时释放。确认 native 是画完再释放，不要每帧释放。克隆失败的退回规则与上面相同。

`LegacyDecoderLibrary.isAvailable()` 失败后把 `loaded = false` 永久缓存，并且在 `synchronized` 里 `System.loadLibrary`。加载失败多半是一次性的（ABI、存储还没就绪），进程内却不再试。结果缓存可以留，dlopen 不要占着锁。失败记时间戳，允许隔一段时间重试一次。设置里的解码诊断提供 `reset()`。

### A21　缓冲、掉帧、offload　P3　先测量

`PlaybackService.buildLoadControl` 固定最小缓冲 15s、最大 60s、回看 30s。下一集预载 30s，下下集 5s。本地大文件这样起播是对的。低内存或本集 `softwareVideoOnly` 时收一档：最大 30s，回看 10s，只预载下一集 5s。其余保持现在的数。不要做连续自适应。探测预热已经有「缓冲领先不足就等」的闸，预载管理器没有。

`MAX_DROPPED_VIDEO_FRAME_COUNT_TO_NOTIFY = 50` 只决定 ExoPlayer 何时回调，应用没有 `onDroppedFrames` 的消费者。软解已经在掉帧时，下一集仍按 30 秒预载，弹幕仍按满密度画。连续超过阈值时，把预载降到上面的低档，弹幕同屏上限临时打到设置值的一半。硬解掉几帧不要降。连续约 5 秒没有新的掉帧回调再恢复。

现在没有 `setEnableAudioOffload`，没有 tunneling，没有 `KEY_PRIORITY`。仅听且编码是 AAC/MP3/FLAC 时可以试 offload，失败回退到现在的 AudioTrack。视频播放不要开 offload。tunneling 默认不开，它和 TextureView、小窗、切轨在部分机型上不兼容。解码器优先级和 operating rate 要有发热对比再默认开。

清单声明了 `WAKE_LOCK`，`PlaybackService` 没有 `setWakeMode`，播放器是默认 `WAKE_MODE_NONE`。先灭屏听一段。会一卡一卡再设 `WAKE_MODE_LOCAL`。不要用 `WAKE_MODE_NETWORK`。

`PlaybackService.onCreate` 在没有偏好缓存时，用 `runBlocking` 读 DataStore，超时 1.5s，然后才建渲染器工厂和 ExoPlayer。有缓存时这条是个位数到十几毫秒，不要动。没有缓存时不要堵在主线程上：用默认值立刻建播放器，偏好在后台读完再补发渲染器模式。不要改成 `runBlocking(Dispatchers.IO)`，那仍然阻塞。冷启动超过约 50ms 再改有缓存的路径。

四个 ABI 的 FFmpeg 都进了同一个 APK。构建产物里 x86 与 x86_64 合计约 20MB，真机几乎用不到。发布包 `ndk.abiFilters` 只留 `arm64-v8a` 和 `armeabi-v7a`，或改走 AAB / ABI split。debug 可以保留 x86_64 给模拟器。落地前确认 NextLib 的 `media3ext` 在去掉 x86 之后，模拟器是否还要单独的过滤器。仓库里的 `prebuilt/x86*` 和 `build-ffmpeg.sh` 里对应的两行一起收。

无镜像、无旋转时 TextureView 多一次纹理拷贝，SurfaceView 更省。换表面会黑一帧，截图要改 `PixelCopy`，小窗源矩形也要分叉。不要为了省一次拷贝单独换。和截图、小窗同一轮再考虑。

## 2. 会话与播放状态

### A5　`PlaybackState.Ready` 是死端　P0

`ExoVideoPlayer` 把 media3 的 `STATE_READY` 映射成 `PlaybackState.Ready`。除了这个产生点，全仓没有消费者。离开 `Ready` 只靠 `onIsPlayingChanged`。

暂停之后拖进度条：页面会先 `pause()`，seek 引发 BUFFERING → READY，而 `isPlaying` 全程是 false，不会再回调。状态停在 `Ready`。跟着错的有：

- 中央播放钮的条件是 `state == Paused`，钮消失。内嵌页同样。
- `FLAG_KEEP_SCREEN_ON` 看的是 `state == Playing`，缓冲较久时屏幕会灭。
- 播放降档看的是 Playing。
- 弹幕的播放判定看的是 Playing，暂停分支和播放分支都会错。

改法：`STATE_READY` 按 `playWhenReady` / `isPlaying` 直接落成 `Playing` 或 `Paused`。不要再对外发 `Ready`。一处修掉上面四条。

> 复核订正（2026-10-15）：`839c4bd` 已经让中央播放钮认 `Ready`（`PlayerScreen.kt:1951` 加了 `|| state == Ready`），那是 `playOnLoad` 落地的副产品，方向与本条**相反**——本条是从映射处不再产出 `Ready`，那句判断随之变成死分支，做本条时一起清掉，别留两份真相。其余三处（`FLAG_KEEP_SCREEN_ON`、播放降档、弹幕判定）与内嵌页、以及新增的 `playbackStarted` 仍只看 `Playing`，本条主体未动。
>
> 落地订正（2026-10-15，E138）：**主体已修**。`ExoVideoPlayer` 的映射抽成纯函数 `npEngineStateOf(playbackState, playWhenReady)`——`STATE_READY` 按 `playWhenReady` 落成 `Playing` 或 `Paused`，`PlaybackState.Ready` 这个数据对象**从契约里删掉**，`PlayerScreen` 那句 `|| state == Ready` 一并清（不留两份真相）。内嵌页的中央 ▶ 原本只认 `Paused`，现在未播放态也点得出来。真机只顺带看到未播放态的按钮还在，"暂停后拖进度条不掉钮 / 常亮不灭 / 弹幕不走错分支"三条**未逐格复拍**。

### A9　在途装载吞掉后到的意图　P1

`PlaybackSession.startPlayback`：同一个 `uri + id` 已经有在途任务时，直接 `await` 旧任务，只补写 `audioOnlyMode`。`restorePosition = false`（从头播）和 `autoPlay = false`（打开但保持暂停）都丢了。

去重要比较意图，不是只比较条目。意图不同就取消旧任务，用新参数重跑。取消必须能打断探测。探测循环已经有 `ensureActive()`，不要退回吞掉 `CancellationException` 的写法。

> 复核订正（2026-10-15）：`839c4bd` 把 `playOnLoad` / `startPlaying` 送进了引擎契约（`PlayerEngineProvider` → `ExoVideoPlayer.setQueue` → `SessionBootstrap`），**「装载落地自己播起来」这一半已经修**，因为它把 pause 的时机问题从调用方挪进了装载本身。但 `PlaybackSession.startPlayback` 的在途去重判据一字未改（仍只比 `uri + id`、只补 `audioOnlyMode`），`restorePosition` / `autoPlay` / `prepareOnly` 照样丢。本条剩这一半。

### A15　队列身份只用项数　P1

`ExoVideoPlayer.selectQueueIndex` 在项数相等时把两份队列当成同一条，并且不看 `loadPending`。探测还在走的那 0.5–1.5 秒里，另一份文件夹如果恰好一样长，seek 会落进无关文件。

加上队列身份（id 序列，或当前装载代际）。装载未完成时走探测路径，不要按项数 seek。

> 复核订正（2026-10-15）：快路径本身已经成立（`selectQueueIndex` 走 seek 而非整表 `setMediaItems`），旧《任务文档》A5 里「日常切集仍整表重设、改 seekTo 要重开装载闸」那条复活动因**作废**，不再挂账。本条只剩身份判据：`mediaItemCount == items.size` 不看 `loadPending`、不比 id 序列。另 `ExoVideoPlayer` 里 `selectQueueIndex` 的 KDoc 还写着「改用整表 setMediaItems」，与本条相反，改代码时一并订正注释。

> 落地订正（2026-10-19，E143）：**已修**。`ExoVideoPlayer` 维护 `appliedQueueIds`（`applyQueue` 时由 `queueIdentity(coreItems)` 写入），`selectQueueIndex` 快路径换成 `canFastSelectQueueIndex`：引擎项数匹配 **且** `!loadPending` **且** `!terminalFailure` **且** applied/请求 id 序列逐项同序；装载未完成一律走 `probeThenLoad`。Unplayable / `clearQueue` / `applyMedia` 清身份；KDoc 已按现码订正（删掉「改用整表 `setMediaItems`」那句）。判据在 `QueueIdentityFastSelectTest` 8 项，**真机切集欠（B22）**。

### A22　服务侧状态跨会话残留　P1

repeat、shuffle、缩放、scrubbing 写在服务侧 ExoPlayer 上。`clearQueue` 的复位清单里没有它们。`stop()` 既不清会话里的 `_loopMode`，也不向引擎下发 OFF。上一段开过单集循环，关掉迷你条再开一段，引擎仍是 `REPEAT_MODE_ONE`，UI 显示 OFF。第一集会无限循环。

拖动进度条时如果页面被销毁，没有走到 cancel，`setScrubbing(true)` 没有配对的 false。三个调用点都在 `PlayerScreen`，没有 `onDispose`。服务侧 scrub 常开之后，自动连播和通知栏的 seek 都降成就近同步帧。

探测判不可播时只把 `appliedUri` 置空，不清 `appliedItems`，也不把 `_currentIndex` 设成 -1。`clearQueue` 会清这两样。之后任何一次 `setSubtitle`（恢复记忆字幕、字幕面板）都可能命中 `canRemountCurrentItem`，`replaceCurrentSubtitle()` 用整表 `setMediaItems` + `prepare()` 把上一部的队列塞回去。用户看到的是报错那条消失了，上一部自己又开始播。

纪律：写在服务侧播放器上的属性，必须在 `setQueue` 和 `clearQueue` 里重新下发一次。`clearQueue` 复位 scrubbing。`PlayerScreen` 增加 `DisposableEffect { onDispose { player.setScrubbing(false) } }`。Unplayable 分支使用和 `clearQueue` 同一份清理清单。

`pendingSeekMs` 在 `prepare()` 时不复位，却被当成恢复位置。换集或挂字幕重建后会从上一笔 seek 的位置起播。`prepare()` 里清掉。

`release()` 不清会话侧的视频表面。会话播放器继续往已经死掉的 Surface 出帧。`release()` 时把表面置空。

### A23　结束、断连、异常

**ENDED。** media3 在 `STATE_ENDED` 上 `play()` 是空操作，不把位置退回 0 就永远停在结束画面。`SessionBootstrap` 有一处已经 `seekTo(0)`，`ExoVideoPlayer.play()`、`PlaybackSession.toggle()`、空格键没有。结束态从中央钮、空格、通知按播放都没反应，只有画面里的重播键有效。

关掉自动连播时，服务用 `setPauseAtEndOfMediaItems(true)`。末帧是 READY 且 `playWhenReady == false`，映射成暂停（经过 A5 之前甚至可能是 Ready），永远不是 `PlaybackState.Ended`。最需要重播 / 下一集的时候，结束层不出现。再按播放会在同一末帧再次暂停。

把「ENDED 先退位再 play」放进 `ExoVideoPlayer.play()`，不要每个调用方记一遍。关掉自动连播时，若位置已经到末尾且不再 playWhenReady，会话把状态译成 `Ended`。

**断连。** `MediaController` 的 listener 没有 `onDisconnected`。断连之后每个命令被 media3 忽略并打一行 W，getter 返回本地快照，不抛异常。后台播放最容易被 LMK 或 `onTaskRemoved → stopSelf` 打掉。UI 冻在最后一帧，进度条不动，播放、暂停、选集、倍速全部空点，没有重连。`pollPosition` 还在主线程上以 4Hz 读这个死控制器。

`PlaybackSession.acquire()` 在要换引擎时先 `release()` 旧的再创建。创建失败后，服务侧还在播，UI 没有控制器，通知变成孤儿。

改法：`onDisconnected` 落成可重试的错误，并用同一个 `SessionToken` 重连一次。`pollPosition` 开头如果 `!isConnected` 就退避，不要继续打。`acquire()` 先把新引擎建出来，再释放旧的。

服务被系统杀掉之后，没有 `MEDIA_BUTTON` 接收者（和小窗按钮是同一个洞）。用户划掉任务时 `onTaskRemoved` 会刻意留下暂停会话，系统回收反而什么都不留。补上接收者之后，冷启动若是媒体键唤醒，从 `HistoryRepository` 最近一条重建会话，不要自动 `play()`。

**异常兜底。** `ExoVideoPlayer` 和 `PlaybackSession` 的 scope 是 `SupervisorJob()`，没有 `CoroutineExceptionHandler`。探测本身会把非取消异常收成 `Unknown`，它下游的建表、装载、字幕重建在裸协程里。`MediaItem.Builder().build()`、非法的裁剪区间、坏的 cue 数据会冒到主线程。周期落盘若抛一次，这条协程永远停，续播看起来还在，进度不再写。

`HistoryRepository` 的 `stateIn` 同样没有 handler。`prime()` 的 `runCatching` 只吞启动那一次。缺迁移时，UI 第一次收集会在 Default 线程上杀掉进程。

两个 scope 挂上 handler：播放侧落成 `PlaybackState.Error` 并打日志；落盘失败要重启这条循环或给出一次提示。持久层宁可只读降级，也不要 destructive migration。Room 从 v2 再加索引时，用 `MigrationTestHelper` 做迁移测试。漏写迁移会闪退；图省事加 `fallbackToDestructiveMigration` 会静默清空历史。schema 已经导出，测试资产要带上。

**倍速写进了全局默认。** 播放页、右栏、内嵌页在用户选倍速时都写 `settings.setPlaybackSpeed`。这个键在设置页的标题是「默认播放倍速」，`SessionBootstrap` 用它当起播值。一部片子里调到 1.5x，下一部和冷启动都从 1.5x 开始，设置页那一行也会变。已经在播的分支又不读这个键，两条路径不一致。

拆成两个键：设置页写默认，只在装载时读；播放页写当前会话，不回写默认。若产品就是「倍速全局持久」，那就把设置页改名，并让已在播的分支也跟上。不要维持现在这种半持久。

**硬件解码偏好。** 进程启动时的预热读和用户刚改的 setter 没有先后保证，预热可能把新值盖回旧值。预热只填空缓存，已经有更新的写入不要覆盖。

**`Kernel.shutdown()` 从未被调用。** 插件 `onStop()` 因此不会跑。`LocalMediaSource` 的 `ContentObserver` 注册在两个 MediaStore 集合上，进程活着就不会注销。不要接在 `Activity.onDestroy` 上，播放服务还在时 Activity 可以先没。接到「进程进后台且没有播放会话」，或至少给观察者一条不依赖 `shutdown()` 的释放。接上之前，先把 `backgroundStartupJobs` 从无锁的 `mutableList` 改成 `CopyOnWriteArrayList`。`boot()` 在 Default 上往里加，`shutdown()` 从另一条线程 `forEach/cancel/clear`，现在会竞态。

**事件。** `FlowEventBus` 是 `replay = 0`、`DROP_OLDEST`。`PlaybackStarted` 被写成给晚进入的详情页用，详情页订阅时那次事件已经丢了。详情页直接读 `nowPlayingSummary`，不要依赖这次事件的重放。

## 3. 性能与重组

### A6　页根热路径　P0

`PlayerScreen` 已经把 `positionMs` 留成 `State`，注释写明不能在页顶 `by` 解包。紧挨着两行又解开了：

- `bufferedPositionMs`。`pollPosition` 每 250ms 写一次缓冲前沿。本机文件播放中，前沿几乎每拍都变。
- `cues`。每来一组字幕都换列表。PGS 可以一秒切好几次。无字幕的回归发现不了。

这两次 `by` 的失效域是整个 `PlayerScreen`。局部函数不是独立重组域。`AudioOnlyScreen` 自己的注释记过：局部函数里解包位置，12 秒内整页重组从几十次变成 0 次的前提是不要在页顶解。`InlinePlayerSurface` 顶上同样解包了 `cues`，并且还有大约二十条收集（轨道、章节、贡献者、睡眠、截屏开关）和舞台、菜单挤在同一个重组域。

`durationMs` 可以继续在页顶解，时长不是 4Hz。

页根修好之后，底栏还会再解一次。`PlayerBottomControls` 在组合期读 `displayPosition` 和 `positionMs`，然后重算 `playerBarLayout`、重建 `BoxWithConstraints`、重发传输键。控制层露出时，传输键和黑底跟着 250ms 走。控制层收起后 `AnimatedVisibility` 会停掉这段订阅。类 PC、有指针、不沉浸时控制层不自动隐藏，这条会一直是 4Hz。擦洗时更密。

改法：缓冲和位置都只留 `State`。时间码和 `NpSeekBar` 拆成文件级叶子，轨道的 fraction 在 `Canvas` 里读 `.value`。Cue 只传给文件级 `SubtitleLayer`，或让字幕层自己 `collect`。`tracks` / `chapters` 挪进真正打开的菜单里再收集。`InlinePlayerSurface` 同样做：菜单才用的流不要放在舞台的重组域。

判据：播 12 秒，页根重组接近 0。控制层常显时，底栏本体接近 0，进度条和字幕仍在走。不要用「看起来还流畅」代替计数。

字幕层现在的签名是 `List<SubtitleCue>`，所以页面不得不订阅。位图 Cue 每个套一个 `BoxWithConstraints`，再用 `Modifier.offset` 做布局位移。PGS 高频换帧时，每条 Cue 都是一次子组合测量。`bitmap.asImageBitmap()` 每次重组包一层。

改法：字幕层接收 `State` 或直接接收 player，在内部收集。位图用一个 `Canvas` 按归一化矩形画，或 `graphicsLayer` 的 translation / scale。`offset` 会触发布局，不要用。文本样式按 `SubtitleStyle` `remember`。

竖屏选集是外层 `verticalScroll` 里再 `forEachIndexed`，没有 key，没有 Lazy。N 集就组合 N 行，滚出屏幕也不出树。同文件的选集面板已经是 `LazyColumn`。内层改成 `LazyColumn`，或直接复用那个面板。同轴嵌套滚动会互相吞，内层到边界不会交给外层。

`AudioOnlyScreen` 的顶栏、信息、传输排、工具芯片仍是局部 composable，捕获外层的 `snapshot`、`ink`、`isPlaying`。进度那次已经拆出去了，这四块没有。提升成文件级函数，显式传值。

全工程的 `MediaItem`、`NowPlaying`、`SubtitleCue`、`SubtitleStyle`、`NpTrack`、`NpChapter` 没有 `@Immutable`。`NowPlaying` 含 `List`，编译器无法证明稳定，父级重组会无条件重组子组件。给这些全是 `val` 的类型加上注解，用 Compose Compiler Metrics 看跳过率，不要凭眼。

### A26　动画值读在组合期　P1

**波形条。** `WaveformSeekBar` 用 `val progress by animateFloatAsState`，再把 `progress` 放进 `LaunchedEffect` 的 key。位置 250ms 一跳，线性补间连着跑，这个 effect 每帧取消再启动。`displayedFraction` 既给语义也给 `Canvas`，整段按帧重组。High 档大约 112 根柱，循环里每根分配 `Offset` 和 `Size`。

**移除动画和轻量档漏网。** `npMotion` 在系统「移除动画」时会换成短淡入。`npDuration` 只乘档位，不看移除动画。只调 `npDuration` 再写裸 `tween` 的地方，轻量档会被夹短，移除动画不会。已经看到的包括：仅听和视频的交叉淡入、手势胶囊、锁定徽标、缓冲圈、库页阶段、标签、顶栏标题、启动交叉淡入、全屏菜单、内嵌顶栏、双击快进的水波、封面 crossfade 的裸毫秒、下拉刷新指示器。`InlinePlayerSurface` 有一处 `tween(npDuration(...))` 连 easing 都没写，用的是 Material 默认曲线。`NpSheet` 的进出场也不走 `npMotion`，轻量档下 Toast 只淡、Sheet 照样滑。`tweenOrFade` 是 public 的，不吃移除动画。

能在组合期调用的，改 `npMotion(token)`。`transitionSpec` 里不能调 composable 的，按 `KernelNavHost` 已有的写法把移除动画折成 `ReduceFade` 再放进 tween。`npDuration` 成为唯一时长出口时，把移除动画折进去，调用点不要再各写一个 `if`。不要新写一套时长。

`NpTrackBar` 在动画 `size` 和 `fillMaxWidth(fraction)`。滑块改固定尺寸，缩放放进 `graphicsLayer`。填充用 `drawBehind`。两端补 `clipToBounds`。

`NpSkeleton` 的流光、`NpEmptyState` 的虚线环，仍在 `draw` 里造 `Brush` / `Stroke` / `PathEffect`。同文件里玻璃面、发丝、封面环已经改成 `drawWithCache`，这两处用同一写法。移除动画时骨架不要 60fps 流光。

轻量档的弹簧被下限压平。`scaled()` 在轻量档乘 0.20 后夹到 45–120ms。`silkStiffness` 把时长 `coerceAtLeast(140)` 再算刚度。120 小于 140，于是 Hover、Panel、Switch、Tab、Drawer、Sheet、Scheme 在轻量档全部变成同一个刚度。实际时长是弹簧自己的自然时长，不是 45 也不是 120。同一屏上走 tween 的动画按夹出来的毫秒走，和弹簧不同步。`MotionTokensTest` 断言「短于 140ms 的令牌全部夹到下限，100 和 0 必须给出同一个刚度」，门禁在保护这个洞。

让刚度下限和轻量档的时长上限对齐，或按目标时长反算临界阻尼刚度，不要用 `8000/ms` 再夹到 140。测试改成：每个令牌在三个档位下的等效时长互不相同，并且不超过该档的上限。

> 落地订正（2026-10-19，E143）：**已修**。`silkStiffness` 下限从 `140` 改成 `NpMotionQuality.lightDurationFloorMs`（45），轻量档 `scaled()` 出来的 45/52/56/64/100/120ms 各自算出不同刚度，Hover/Press/Field/Panel/Switch/Tab 不再同速；KDoc 写明 45ms 处的共享是 `scaled()` 夹具下限的设计折叠。`MotionTokensTest` 重写：26 令牌在三档下 `8000/sqrt(k)` 逆函数与 `npDuration` 相等（±0.5ms）、轻量档刚度互异且单调、平衡档内按令牌区分。**上面「改法」里「每个令牌在三个档位下的等效时长互不相同」不成立**——Balanced/High 的 `durationFactor` 都是 1f，三档必然重合两档；门禁按「轻量档与另两档互异 + 档内区分」落。

列表项的 `animateItem` 有两套。播放页只传了 fade，placement 吃 Compose 内置 spring，档位和移除动画对它无效。库页把 `placementSpec` 设成 null，位移动画直接没了。收成一套带 placement 的规格，placement 走 `npMotion`。库页关掉 placement 是为了避免整屏搬家抖动，改成限幅，不要永远全关。

`npPanelEntrance` 只有入场。退场卸载用固定 `delay(160)`，和 `npMotion(Motion.Field)` 的真实时长不是同一个数。轻量档下动画早结束，面板还占着命中；若令牌改长，动画会被中途卸掉。`exitMs` 用 `npDuration(Motion.Field)`，或等动画结束回调再 `onRemoved()`。

`NpMenuSurface` 打开时有 scale 和 fade，`open = false` 时 Popup 直接离开组合，没有退场。`NpSheet` 关闭靠 `delay(时长 + 32)` 和拖拽 `animateTo` 两条路径，用两个布尔互斥。收成一个状态机，`onDismiss` 只在离开动画结束时调一次。菜单用同样的可见性状态包住移除。

倍速胶囊、竖滑 HUD、结束层、错误面板是硬切。倍速从 1.25 回到 1 时，下面的续播提示还跳 32dp。这些包上和手势提示、控制条同一套 fade。切集现在是值一换就重绘，并且 `selectQueueIndex` 之后立刻 `controlsVisible = false`。新集还在装载，屏幕上什么都不留。标题和时长做一次短交叉淡入。切集后保持控制层可见，让自动隐藏按正常节拍收。

Tab 胶囊、内容转场、图标缩放用了三个时长（大约 220、280、180）。`Motion.Tab` 的注释还写着它负责内容淡移，内容侧已经换成另一组令牌。收成一档，并改注释。分段控件 `.seg` 的选中块是硬切，和 Tab 的滑动胶囊不是一套。选中块用滑动色片，阴影层常驻。

Tab 胶囊的槽位初值是 `IntRect.Zero`，量不到就 `return`。从播放页回来或旋转之后，第一帧没有选中块，第二帧才弹出。量不到时用等分估计先画，下一帧用真实矩形盖掉。`tabShiftDirection` 不要只留最后一个整数，快速连点会把方向盖错。

系统「移除动画」只在组合时读一次 `ANIMATOR_DURATION_SCALE`。运行中打开之后要重建才生效。用 `ContentObserver` 写进 `LocalNpReduceMotion`。触摸浏览打开时，关掉骨架流光、唱片旋转、水波这几类循环动画。

两套共享元素互不相通。卡片进播放页是一套，播放页回右栏是另一套。类 PC 从右栏点封面进播放页没有正向飞行。`paneBounds` 不随旋转失效。用某个 object 上的可空状态关掉 `NavHost` 转场，顺序靠人守。飞行用的 `Bitmap` 不回收。`Motion.Shared` 的名义是卡片到播放页，右栏宽度动画也在用它。

收成一个交接：登记源矩形、目标矩形、快照、超时。`NavHost` 看交接句柄，不读全局 null。矩形随配置变化作废。快照用完回收。右栏宽度单独一个令牌。

外层路由转场对所有页面一刀切，入场滑入大约四分之一屏宽。播放页这种全屏视频不该吃同一次推动。`ScreenProvider` 可以声明自己的转场，播放页只用淡入。内层已经禁止大幅整页滑，外层要么收到同一量级，要么在令牌注释里写明外层允许。

`NpCoverAccent` 的缓存是三段式，失败结果不失效，并发不原子。失败不要永久占着条目。

弹簧只能从 `npMotion` 出去。`silkSpring` / `bouncySpring` 保持 `internal`。新代码继续走 `npMotion`。漏的是调用点，不是再设计一套时长。

### A34　控制器侧的缓冲前沿不更新　P1　（本轮采出）

`ExoVideoPlayer.pollPosition` 每 250ms 读一次 `c.bufferedPosition` 写进 `_bufferedPositionMs`（值变了才写）。实测（E140，探针 + `dumpsys`）：**稳态播放 12 秒里这一次读取的值一次都没变**——会话侧的 `buffered position` 在推进（237824 → 248426），但 `MediaController` 侧拿不到。会话没有把缓冲前沿的推进推给控制器。

后果：进度条三段式的「已缓冲」段（S5 的中段）**从开播那一刻起就是死的**。本机文件缓冲远领先播放位置，看着像"整条都缓好了"；一旦前沿真的在动（大文件前段、外置存储慢、将来接非本地源），这一段不跟走，还会被既有的"只有领先才画"守卫整段藏掉。

改法（未做）：前沿要么由会话侧**推送**（自定义命令/周期通知，走 `np.scrub` 那条转发路），要么控制器按已知码率外推。别指望 `MediaController.bufferedPosition` 自己跳。判定：起播后缓冲段与 `dumpsys media_session` 的 `buffered position` 同步推进；顺带补一条前沿不变的夹具钉住"不画假缓冲"。

## 4. 操作

### A7　手势开关和死区只覆盖了拖动层　P1

`StageGestureLayer` 里点按那条 `pointerInput` 的 key 是 `Unit`。`gesturesEnabled` 只在协程启动时被捕获。拖动那条的 key 才是 `gesturesEnabled`。所以锁屏或在设置里关掉手势之后，横滑、亮度、音量会停，双击快进和长按 3 倍速不停。看起来像设置生效了，因为拖动确实停了。

点按用来唤出解锁钮，这个例外保留。双击和长按必须看当前值。key 改成 `gesturesEnabled`，回调放进 `rememberUpdatedState`，不要把 lambda 本身当 key，否则每帧重启手势。横滑夹取用的时长同样被冻在首帧。AVI 时长回填之前首帧常是 0，夹取上限变成 1，横滑直接废掉。页内切集后仍按旧集时长夹。时长在回调里读 `durationState.value`。

回归：锁定后双击不 seek，长按不变速，单击仍能唤出解锁钮。设置里关掉手势后同样成立。

左右 24dp 和上下 48dp 的死区只写在拖动那个 `pointerInput` 里。点按族的 `detectTapGestures` 在边缘和顶部照样接收。沉浸时系统栏要靠顶部下滑临时叫出。顶部下滑可能被点按或横滑吃掉。左右边缘的返回可能变成双击快进或长按 3 倍速。

点按层使用同一套豁免：左右 24dp、顶部 48dp 不消费。边缘宽度取 `max(24.dp, systemGestures inset)`，不要只写死 24dp。边缘双击少一截，可以接受。不要为了避让把全屏手势关掉，也不要把整条边放进 `setSystemGestureExclusionRects`。

拖动层里，死区判断排在「横向位移更大就判成 Seek」之后。底部 48dp 的 home 手势区起手做横向滑动，会先被判成 seek 并 `consume()`，系统回桌面拿不到事件。顶部状态下拉同样。死区判断提到分轴之前，横竖都不接管。底部死区用系统手势 inset，不要只写 48dp。

`awaitFirstDown(requireUnconsumed = false)`，并且之后不看 `isConsumed`。手势挂在舞台 Box 上，进度条是它的子节点。拖进度条时舞台也在 seek 或调亮度。改成 `requireUnconsumed = true`，或在循环里跳过已消费的事件。更干净的是只把舞台手势挂在画面节点上，不挂在整页。

长按 3 倍速有反向守卫：seek 开始时会结束加速。没有正向守卫。一次慢的横滑，超过长按时间才过 slop，会先 `setSpeed(3f)`。用户以为在拖进度，画面以 3 倍速播到松手。`onLongPressStart` 时若已经在拖，直接返回。按住期间位移超过 slop 就取消加速。

竖滑定义了 `onVerticalEnd`，`PlayerScreen` 没有传。HUD 只靠大约 900ms 的超时消失。抬手后应立刻收，或只留 200–300ms。

单击和双击注册在一起。`detectTapGestures` 会等双击超时才回调单击，控制层大约 300ms 后才出现。显隐延后提交。超时内发生双击就取消这次单击，再执行 seek 或暂停。不要先切再撤销，连点会闪。

半锁。竖屏锁定只盖住视频区，信息区的主操作没有门控，返回键在锁定时却被吞掉。两处选一个：若锁定只保护画面，返回键不要吞；若锁定是整页防误触，信息区主操作也要禁用。仅听页自己的返回不要锁死。暂停并且锁定时，解锁钮和控制层永不自动隐藏，和「锁定后只留解锁钮，并且它会隐去」相反。这条隐藏逻辑要把锁定态算进去。

自动隐藏的 key 不含横滑、竖滑和 Buffering。手势进行中，控制层仍按旧节拍收起。这三态变化时重置计时。

> 落地订正（2026-10-19，E143）：**主体已修，第⑧条半锁仍挂**。①~⑦、⑨的落点：点按族 key 改 `gesturesEnabled`、回调走 `rememberUpdatedState`；两族 `awaitFirstDown(requireUnconsumed = true)` 且死区先于分轴；死区左右/底部取 `max(24dp/48dp, WindowInsets.systemGestures inset)`（`PlayerScreen` 计算后传入，不用 `safeDrawing`）；长按 3x 正向守卫（过 slop 立即撤销加速）；`onVerticalEnd` 接线；`seekByGesture` / `onSeekGestureDelta` 在回调期读 `durationState.value`；单击延迟到双击超时后提交；多指只取主指针；自动隐藏 key 补 `seekGestureActive/verticalGesture/stageLocked`。**第⑧条（半锁语义）未动，等 D3**；A27 的「横滑按片长满幅」未做。策略测试 `StageGesturePolicyTest` 16 项；**真机死区/系统边缘手势/锁定与关设置后的双击长按全欠（B22）**。

### A27　横滑、双击、倍速条、触控尺寸

满屏宽度现在固定换算成 ±90 秒。20 秒的片子一滑就出界，两小时的片子要滑很多次。

满幅改成跟片长走：片长短于或等于 30 秒时，满幅等于片长；否则满幅等于片长夹在 30 秒和 180 秒之间。松手才 `seekTo`。不要改成拖动中连续 seek，那会把气泡手感打回关键帧乱跳。不要加 fling。

时长未知（`durationMs == 0`）时，双击快进会 seek 到 0，并给 Reject 触觉。装载瞬间双击等于回到片头。时长未知时双击不 seek。

相同的手势提示文案在 1.2 秒内再次触发时，计时不重置，第二次反馈被截断。每次触发都重新计时。停留时长和手势 HUD 的 900ms、续播提示的 3.2 秒收成命名常量，不要三套魔法数。

`SPEED_PRESETS` 是六档，含 3.0。`SPEED_PORTRAIT_PRESETS` 只到 2.0。长按加速仍是 3x，全屏菜单也是六档。竖屏芯片补上 3.0。窄宽度用已有的大字号折列，不要把 3x 挤出屏幕。

竖屏进度条的触控带是 18dp。文档写 26dp，无障碍最低 44dp，Android 建议 48dp。倍速步进钮大约 34dp。设置里的开关行整行不可点，命中区只有大约 46×27dp 的开关。进度条至少 44dp。设置行整行可点。

> 复核订正（2026-10-15）：① 触控带分两路——拆行（`Split`）那一路仍 18dp，单行（`SingleRow`）那一路已经有 `coerceAtLeast(touchTarget)`，本条只剩前者。② 同族的两处**读数抖动**已在 `839c4bd` 修掉：新增 `NpStableWidth` 给 seek 气泡的增量与目标时刻、竖滑亮度/音量竖条的百分比按最宽样本定宽（真机实报「一次竖滑条子在屏幕上走三段」）；`PlayerBarLayoutTest` 也改成按时间码真实字符数预算（7 字读数 `1:00:00` 比 5 字宽 14.4dp，360dp 竖屏两枚 7 字必须先省总时长）。这两处的**设备复拍**没做，挂在 B3。

亮度、音量的 `rememberSaveable` 只负责回显，不把值写回窗口。内嵌页在 `DisposableEffect` 里记住旧亮度，离开时写回，所以内嵌里调好的亮度会在收起右栏或翻转截屏开关时跳回去。全屏页只写不恢复，回到媒体库仍停在手势留下的亮度上。见 A8，两处用同一个助手。

多指同时拖时，位移被加在一起，双指等于双倍增益。只取一根指针。

`onPress` 抬手无条件调用 `onLongPressEnd`。没有长按过就不要结束加速。

拖动开始之后不再复核边缘。手指从中间滑进系统返回区，仍被播放器消费。起手死区保留，滑进边缘时把事件让回去。

键盘。播放页根上 `onPreviewKeyEvent` 把方向键 consume 掉。根节点 `focusable()` 并且进场抢焦点，没有 `focusProperties`。外接键盘和遥控器够不到选集、倍速、字幕、截图、小窗、音轨。菜单 Popup 打开时，焦点在 Popup 里，页面级的 Esc、空格、方向键很可能收不到。控制层自动隐藏会让持焦按钮离开组合树。

方向键只在没有子节点持焦时承担 seek 和音量。顶栏和底栏定义焦点顺序，并用 `focusRestorer`。控制层隐藏前把焦点交还根节点。Popup 内自己处理 Esc、方向和确认。

`SessionKeys` 只有空格、左右、Shift 加左右、上下、M。媒体键、`J` / `K` / `L`、数字跳转百分比、括号调倍速都不在表里。浏览态的静音用 `setStreamVolume` 且 flag 为 0，不弹出系统音量条。补上媒体键和这几组播放键。音量写入带 `FLAG_SHOW_UI`。逐帧仍是未做的能力，不要在键位上假装已经逐帧。

`MainActivity` 的键兜底只有一个槽。长按重复时，后一个 DOWN 会盖掉前一个，UP 可能发错。按键各自记是否被消费。

播放页根节点的键盘焦点只在首帧请求一次。从菜单回来不会回来。焦点丢失后若仍在播放页，再请求一次。

删除确认没有 `BackHandler`。遮罩盖不住外壳的底栏和迷你条。返回键会在确认框还在时退出页面。确认框吃掉返回，遮罩盖住外壳上的可点区域。

「移除扫描目录」没有二次确认。移除最后一个会静默清空列表、快照和缩略图缓存。下一次扫描要重新抽全库的帧。最后一个目录要确认。

聚合页的「选集」打开的是第一个多集目录，其它目录的集不可达。文案在两处也不一样，一处把「本层视频数」说成「包含多集的条目数」。选集必须带目录身份。两处文案用同一个计数。

「最近搜索」没有删除。`clearSearchHistory()` 没有调用点。上限 5，错词会一直占着。每条可删，或提供清空。

`READ_MEDIA_VISUAL_USER_SELECTED` 已经在清单里，权限是否齐全的判断没有用它。「仅部分访问」可能被当成完全未授权。把这个权限纳进判据，并允许用户补选目录。

进度条两套手感。`NpSeekBar` 没有长按，起手的 x 没有夹进轨道。波形条不能点，只能相对拖，满幅等于大约一半时长。菜单里的滑杆没有吸附。点按波形应跳到对应位置。菜单滑杆在档位上吸附。

无障碍。进度轨、底栏 Tab、菜单选中态在无障碍树里没有名称或状态。accent 色被当成正文色时，亮色底上对比不够。补 `contentDescription`、`stateDescription`、选中态。正文不要用 accent 当字色。

`DesignTokens` 里有的尺寸，组件仍大量写字面量 dp。`trackCornerRadius`、`trackBarHit` 从加进来就没有引用。新代码用令牌。没有令牌的尺寸先补进 `DesignTokens`，不要再复制一份。

## 5. 亮度

### A8　全屏亮度　P1

竖滑写的是 `activity.window.attributes.screenBrightness`，不是系统亮度。窗口若还是 `BRIGHTNESS_OVERRIDE_NONE`（跟随系统），初值被写成 0.62。第一次滑动才把覆盖值写进 Activity，所以第一下从假的 62% 起跳，不是从当前系统亮度起跳。音量在竖滑起手时会重读系统值，亮度没有这一步。

内嵌播放器在 `DisposableEffect` 里记住旧值，离开时写回。全屏 `PlayerScreen` 只写不恢复。从全屏播放返回媒体库，库页和设置页停在手势留下的亮度上，直到进程重启或再进内嵌页。内嵌那份「恢复」还会在错误的时机把用户刚调好的值写回进入前的旧值，因为那个字段是从截屏开关的 effect 里抄来的。

两处用同一个助手。进入时记住当时的 `screenBrightness`，包括 `BRIGHTNESS_OVERRIDE_NONE` 本身。离开播放页时写回这个原值。`NONE` 就写 `NONE`，不要写回 0.62。动手前的 HUD 不要显示 62。小窗期间不要恢复。回到全屏后，仍用这一次播放里用户滑过的值。内嵌页删掉那份会误回滚的 `previousBrightness`。

> 落地订正（2026-10-19，E143）：**已修**。新增 `brightness/BrightnessPolicy.kt`（纯策略）与 `BrightnessAssistant.kt`（`rememberWindowBrightness`），全屏 `PlayerScreen` 与内嵌 `InlinePlayerSurface` 共用：进入 capture 原值（含 `BRIGHTNESS_NONE = -1f`）、离开 restore 精确写回（`NONE` 就写 `NONE`）；`currentPercent()` 先看窗口 override ∈ (0.01, 1]，否则读 `Settings.System.SCREEN_BRIGHTNESS` 换算，读不到兜 **50**（不再 62）；`setPercent()` clamp 1..100 且与平台现值差 <0.001 不写；竖滑起手 `refreshFromPlatform()`；`isChangingConfigurations` 跳过、配置变化重建按 `touched` 重应用；PiP 不触发 restore；内嵌页截屏 effect 只留 FLAG_SECURE，`previousBrightness` 误回滚删除。判据在 `BrightnessPolicyTest` 11 项，**真机离开恢复/转屏/PiP/初值欠（B22）**。

## 6. 小窗

手动入口、`onPictureInPictureRequested` 返回 true、离开播放页清参数、仅听音频直接拒绝、`configChanges` 包含进出小窗所需的项、比例钳制 `0.419..2.39`：保持。不要提前把比例写进 Activity，那会让库页和设置在部分系统上跟着进小窗。不要在 `onUserLeaveHint` 里调用 `enterPictureInPictureMode`。

### A2　按钮到不了服务　P0

`pipActions` 用 `PendingIntent.getService`。Intent 只有 `ACTION_MEDIA_BUTTON` 和 `setPackage`，没有组件。合并清单里没有 `MEDIA_BUTTON` 的 action。`PlaybackService` 只声明了 `androidx.media3.session.MediaSessionService`，没有 `onStartCommand` 把媒体键转成会话动作，也没有 `MediaButtonReceiver`。

这个 Intent 按「显式」的定义可以成立（action 加 package），解析时本包内没有 service 能接住，`send()` 静默无操作。小窗上仅有的暂停和下一集，点了没反应。耳机和蓝牙媒体键被系统杀掉服务之后，也没有重启链路。

改法：使用 media3 的 `MediaButtonReceiver.buildMediaButtonPendingIntent`（广播），在 exo 插件的清单里注册 `androidx.media3.session.MediaButtonReceiver`，`exported=true`，并 `MediaSession.Builder.setMediaButtonReceiver`。播放页 UI 模块不要直接依赖 exo 的类，避免环依赖。若必须 `getService`，Intent 要 `setClass` 到 `PlaybackService`，并确认 `onStartCommand` 会把 `ACTION_MEDIA_BUTTON` 交给 session。

先修通这两颗，再加按钮。改完在真机上点暂停和下一集，看会话状态变了没有。模拟器能画出按钮不算通过。

> 落地订正（2026-10-15，E138）：通路改成**引擎给广播 PendingIntent**——`VideoPlayer.mediaButtonIntent(NpMediaButtonAction): Any?`（`kernel-api` 是纯 JVM 模块，Android 类型按 `attachDisplay` 同一姿势以 `Any` 出现），`ExoVideoPlayer` 用 `PendingIntent.getBroadcast(component = androidx.media3.session.MediaButtonReceiver)` 实现，`plugin-player-exo` 清单注册该 receiver。**上面改法里那句 `MediaSession.Builder.setMediaButtonReceiver` 作废**：media3 1.11.1 没有这个 API（javap 过 `MediaSession$Builder`），链路是"广播 → receiver → `startForegroundService(PlaybackService)` → 会话执行按键"，服务侧不用改。UI 侧引擎没给通路就**不画那颗钮**。真机：▶ 点下去会话 `PAUSED→PLAYING`、logcat 见广播落到 `PlaybackService`、`dumpsys media_session` 里本包有了 `Last MediaButtonReceiver`；⏭ 那颗没点中（换 `keyevent 88` 只证明会话能力在位）→ **B21**。

### A14　小窗里的画面和叠层　P1

`isFullscreen` 等于窗口是横向。9:16 的小窗窗口是竖的，于是进竖屏版式。那里竖视频高度是 `maxHeight * 0.55f`，外壳是主题色。顶栏在 `inPipMode` 时会藏，55% 限高不会。小窗里画面只占一条，上下是设置页那种底色。

`inPipMode` 时不要走竖屏 / 横屏分派。单独一层黑底，画面铺满。55% 只留给普通竖屏播放页。放大回来时以 `inPipMode` 优先，避免窗口尺寸一变就闪成另一种版式。

进入小窗时会 `controlsVisible = false` 并收起弹层。这个 effect 只有进入分支。点系统的展开回到应用后，控制层不会回来。自动隐藏只会从 true 变成 false，没有路径把它拉回 true。若设置里关了手势，连点画面都点不出控制层。竖屏常驻的播放条用裸 `if` 弹回来，控制层还藏着。

effect 改成两边：进入就收起，退出就把 `controlsVisible` 设为 true。常驻播放条的进出用和迷你条一样的显隐动画。

「小窗只留画面」只藏了顶栏和一部分底栏。倍速胶囊、续播提示、手势胶囊、缓冲圈、字幕、弹幕仍在。`VideoStage` 的参数里没有 `inPipMode`。小窗短边只有两百多 dp，一颗 13sp 的倍速胶囊能占掉大约四分之一宽。字幕按全屏字号既读不清又压画面。弹幕继续每帧画。

`VideoStage` 增加 `inPip`。为真时不画字幕、弹幕、缓冲圈、倍速胶囊、续播提示、手势提示。不要维持全屏字号，也不要在小窗里做亮度音量手势。`stageGestures()` 关掉，避免误触快进和长按。结束层如果还在，里面的重播和下一集在小窗里可点，和系统按钮叠在一起，同样关掉。

`setSeamlessResizeEnabled(false)` 时，捏合或比例变化用一帧截图缩放，表现为顿一下。视频打开无缝缩放。`setSourceRectHint` 现在是 TextureView 的整窗矩形，适应模式下包含黑边，过渡会把黑边收进小窗。源矩形改成画面内容区：用当前宽高比、缩放模式和 View 尺寸算内接矩形。180° 旋转不改变宽高比，现在不要按 90° 去改比例。

`PictureInPictureParams` 是整份替换。进入时带了源矩形，之后 `LaunchedEffect` 重发参数时 `sourceRect` 默认 null，上一次的 hint 被清掉。比例从 0 变成真实值时，会先按 16:9 成形再硬跳。三处在写参数：`MainActivity` 的 `onResume` / `onUserLeaveHint` 发一份只有 `setAutoEnterEnabled(false)` 的空参数；播放页 dispose 时清动作；小窗期间发全量参数。`onResume` 之后 Activity 上留下的是「无比例、无动作」。OEM 的小窗手势若在没有显式参数时触发，拿到的就是这份空的。

收成一个写入点。每次发布都带上当前的比例、动作、源矩形、无缝开关。和上一次相同就不要打 binder。进入前若比例还是 0，先等 `videoAspectRatio > 0`，不要先按 16:9 跳一次。源矩形和系统栏、刘海求交后再传。

竖向小窗会清掉横屏锁。`LaunchedEffect(isFullscreen)` 在窗口不再横向时把 `orientationLock` 设回跟随传感器。用户点过锁定横屏，从小窗回来锁没了。小窗期间冻结方向锁，退出再恢复进入前的值。小窗内 `requestedOrientation` 用 `UNSPECIFIED`，免得和比例请求打架。系统旋转锁关着时，用现有的「方向已被系统锁定」提示，不要循环请求转屏。

关掉小窗会结束进入小窗的那个 Activity。入口是 `singleTask` 的 `MainActivity`，播放页只在组合里听小窗变化，Activity 没有 `onPictureInPictureModeChanged`。点小窗的关闭，结束的就是整个任务。后台播放开着时服务也许还在，界面栈没了。后台播放关着时 `stop()` 还会把睡眠定时一起清掉。

关小窗时不要让任务死掉。独立的小窗 Activity，或在关闭回调里把任务留在后台并回到媒体库，播放继续交给前台服务和迷你条。放大仍回原来的播放页。验收标准是真机点一次关闭：任务仍在最近任务里，后台播放开着时声音还在。模拟器能画出小窗不算通过。

手动入口先把「已经请求过」置位，`enterPictureInPictureMode` 的失败结果被丢掉，本轮不再重试。标志若在 `rememberSaveable` 里，旋转或复用路由之后第二次点完全无反应。失败时清标志，toast 保持。成功才置位。

`FLAG_SECURE` 有两个主人。`PlayerScreen` 和 `InlinePlayerSurface` 各自 `addFlags` / `clearFlags`。内嵌页的 `onDispose` 无条件清除，会把播放页刚设上的禁止截屏清掉。这个 flag 是窗口级的，开了之后整个 Activity 都不能截。部分系统上带这个 flag 无法进入小窗，`enterPictureInPictureMode` 返回 false，toast 却只说「画中画不可用」。设置文案只说了禁止截屏和录屏。

收成一个引用计数或单一持有者。内嵌页离开时，只有自己加过的那次才清除。设置行写明「开启后画中画不可用」。`enterPip()` 在开关为真时用这句 toast，不要用泛化的失败文案。进入小窗前不要偷偷清掉用户打开的禁止截屏。

小窗动作补上一集，到此为止。不要超过三个。快退不加。图标更新只在已经进入小窗之后做。

小窗短边只有两百多 dp，继续按全屏分辨率解码，耗电和全屏一样。不要改解码器的最大分辨率，回到全屏会糊一阵。至少把预载收到低档，并停掉弹幕。这是 P3，和掉帧反馈同一轮。

从右栏点画中画会先 `navigate` 到独占播放页，再等 `mediaOpened` 才 `enterPip()`。退出小窗时窗口仍是横的，那条「进入类 PC 档就回到右栏」的 effect 不触发。用户回到整屏播放页，而不是原来的三栏。小窗动作提到会话上，由当前持有画面的表面发布参数，不要为了小窗再压一层路由。若必须压路由，退出小窗（`inPipMode` 从 true 变 false）时回到进入前的浏览态。

迷你条点回播放页总是带完整 uri、标题、mime 的新路由。切集后若条上的快照旧了，会用过期参数再走一次 `startPlayback`。增加一条不带参数的播放路由，页面从会话读当前项。

迷你条的关闭是 `session.stop()`，清队列、清通知，没有撤销。误点的成本高。给一个几秒的「已停止，撤销」。下滑收起条但不能等于停止：收起只藏 chrome，停止仍是那个关闭钮。跟手位移写在 `graphicsLayer`，不要每帧改布局高度。

迷你条用 `BoxWithConstraints.maxWidth < 360.dp` 决定是否收进溢出菜单，同文件又在读 `LocalNpWindowInfo`。窄档判断收到窗口信息里，不要每个页面写一个阈值。

封面有两条解码路径。迷你条注释写本模块没有 Coil，依赖里却有，并且自己用 `BitmapFactory` 解一张图，没有 Coil 的缓存。右栏用的是 `AsyncImage`。迷你条改用 `AsyncImage`，删掉那条自制解码和未使用的 `miniVisible`。

画面比例、镜像、旋转存在页面的 `remember` 里，进页先按 FIT 画一帧，再异步读出 CROP 或旋转。右栏和全屏各持一份，DataStore 往返期间两套呈现。收到 `PlaybackSession`，和字幕偏移一样，所有表面读同一份。在第一帧之前回填。

仅听的判断不一致。右栏看会话是不是音频。内嵌还要求摘要非空且 uri 相等。摘要为了少重组，切页时会短暂为 null，于是仅听会先挂一次视频 Surface，再换成音频页。两处都看会话的音频态。摘要为空时保持上一帧，不要切到视频舞台。

折叠屏只存了一个布尔，铰链的位置和方向没有往上抛。分屏或自由窗口拖边框时，`isDesktopLike` 用宽高比 1.4 做阈值，拖一下就 `navigate` 或 `pop`。交接改成方向翻转，或进出用不同阈值。至少给出「铰链是否挡住条」的布尔，让迷你条和右栏顶栏能改成单列。

## 7. 状态栏

自绘时钟和电量只在沉浸、系统栏被藏起时出现。类 PC 不画第二份。时钟对齐到下一分钟，不要改成每秒刷新。电量用粘性广播，不要改成轮询。`registerReceiver` 在 target 36 上带 `RECEIVER_NOT_EXPORTED`。顶栏和底栏走 `WindowInsets.safeDrawing`。这些保持。

### A13　图标明暗不跟应用主题　P1

`MainActivity` 调用的是无参 `enableEdgeToEdge()`。应用主题可以独立于系统（强制暗色时系统仍可能是亮色）。全工程没有 `isAppearanceLightStatusBars`，也没有按应用主题构造的 `SystemBarStyle`。缺省按系统深色决定图标前景。系统亮色、应用强制暗色时，状态栏图标是深色，压在深色顶栏上几乎看不见。反向则是白图标压白底。

`values` / `values-night` 的 `windowBackground` 也只跟系统。强制暗色、系统亮色时，冷启窗口、任务快照、旋转时的边是白的。小窗比例和源矩形对不齐时，露出的底也是这层颜色，会出现白边。

主题解析出当前是不是暗色之后，设置 `isAppearanceLightStatusBars = !isDark`，导航栏同样。`enableEdgeToEdge` 显式传入与应用主题一致的 `SystemBarStyle`。`windowBackground` 两档都用深色，或按应用主题取值，不要只跟系统 night。不要走已经废弃的 `statusBarColor`。

> 落地订正（2026-10-16，E142）：**本条整条未动**。只是顺手把另一件事做了——`enableEdgeToEdge()` 的默认导航栏样式是 `auto(...)`，androidx 1.9.3 在这个样式下会把栏色置 0 并**把对比度交回框架**（`setNavigationBarContrastEnforced(nightMode == 0)` → true），于是系统在小白条背后自己垫一层灰；现在 `MainActivity.kt:264-270` 在其后显式改回 false。这**不影响本条的前提**：图标明暗仍按系统深色决定、`windowBackground` 仍只跟系统 night，强制暗色 + 系统亮色时该看不见的还是看不见。验收本条时别把"遮罩没了"当成进展。

### A28　沉浸时钟和电量　P2

`StatusClockBattery`：

- `SimpleDateFormat` 在 `remember(context)` 里建一次。播放中改 12/24 小时制，或改时区，要离开页面才变。12 小时制的格式是 `h:mm`，没有上午下午。下午 1 点和凌晨 1 点一样。听 `ACTION_TIME_CHANGED` 和 `ACTION_TIMEZONE_CHANGED`，收到就重建格式并立刻写时间。用 `DateFormat.getTimeFormat`，或 `h:mm a`。AM/PM 会加宽，时钟限最大宽度，避免把标题挤没。刷新仍对齐整分。
- 电量只取 level 和 scale。充电、低电量都是同一枚图标。`readBatteryPercent` 读不到粘性广播时返回 100。这会在异常时显示满电。返回可空，空就显示「—」，不要显示 100。加上 `EXTRA_STATUS` 或 `EXTRA_PLUGGED`。充电时的读屏至少要说「正在充电」。低于 15% 用 danger 色。不要做五格动画。
- 初值在 `remember { }` 里同步读电量，这是组合期的 binder。初值改由注册粘性广播的第一次回调给出。
- 组件挂在控制层的 `AnimatedVisibility` 里。控制层每 3.5 秒隐藏、再被点出来，都会拆掉并重新注册接收器。

沉浸且控制层自动隐藏时，时钟跟着顶栏卸掉。系统栏已经 `hide`，自绘时钟的理由是「系统栏没了还能看时间」，实现却在几秒后和顶栏一起没了。看片的大部分时间既没有系统时间，也没有应用时间。

控制层隐藏后，在 `safeDrawing` 的刘海区内留一枚低对比时钟，几秒后降透明度，不要把组合卸掉。控制层出来时并回顶栏，避免两个钟。竖屏系统栏还在，保持不画第二份。接收器的生命周期跟这枚常驻时钟，不要跟显隐动画。

横窗一律当成沉浸：`isImmersive = !windowIsPortrait`，然后 `hide(systemBars())`。平板横屏、桌面自由窗口、分屏横窗也会丢掉状态栏。自绘只能补时钟和电量，补不了通知、蓝牙、勿扰。沉浸改为「手机式横屏」，类 PC 横窗可以藏导航栏，保留状态栏，顶栏让位。`hide` 与手势导航共存时，第一次上滑只唤出临时系统栏，会和舞台底部死区抢手势。死区使用系统手势 inset 之后，这条一起看。

`systemBarsBehavior` 设了之后，离开沉浸没有恢复。离开时写回进入前的值。

刘海。顶栏已经走 `safeDrawing`。没有在打孔屏上量过沉浸之后 inset 是否仍含 cutout。不要另写一套状态栏高度。短边刘海测失败再改 inset，不要预防性加 padding。

预测式返回没有接。`NpSheet` 里有一个 `BackHandler`，同文件注释已经说明聚焦的 Popup 会自己吞掉返回键，这个 handler 收不到，却仍占着分发栈，页面级的返回在它下面。删掉或关掉这层。播放页和 Sheet 若要跟手返回，再单独接预测式返回，不要和这次删死代码绑在一起。

## 8. 字幕、弹幕、截图、睡眠

### A3　外挂字幕被改名成 `.srt`　P0

`SubtitleFile` 在需要转码时，把副本写成 `"${stem}-${digest}.srt"`。扩展名写死。`SubtitleCharset` 对 UTF-8 BOM 返回 `needsRewrite = true`。`ExoVideoPlayer.subtitleMime` 只看 uri 末段：`vtt` 用 VTT，`ass` / `ssa` 用 SSA，`ttml` / `xml` / `dfxp` 用 TTML，其它用 SubRip。

GBK、Big5、带 BOM 的 `.ass`、`.ssa`、`.vtt` 转码后交给 SubRip。`Dialogue:` 和 `WEBVTT` 对不上时间轴，一条 Cue 都没有。BOM 是 Windows 和字幕组导出 ASS 的常见形态，media3 自己认得 BOM。菜单仍显示「已挂载」，读的是原始 uri。同目录自动匹配把 ASS 排在前面，这条路径会碰到。

副本扩展名沿用源文件。或者返回 uri 加 mime，挂载时显式传类型。UTF-8 无论有没有 BOM 都不要重写。只有确实要转码时才落副本。

> 落地订正（2026-10-15，E138）：走的是**第二条**（格式显式传），因为回源码核出**本条还有第二条根因**：同目录自动匹配回来的字幕 uri 是 `content://media/external/file/1234`，**末段是数字 id、根本没有扩展名**——只改副本名，自动匹配的 `.ass` 仍会被 `subtitleMime` 判成 SubRip。于是 `NpSubtitleFormat` + `VideoPlayer.setSubtitle(uri, format)` + `SubtitleFile` 用 `OpenableColumns.DISPLAY_NAME` 判格式，副本扩展名取自格式白名单。**「UTF-8 带 BOM 不要重写」那半没做**：media3 1.11.1 的 `androidx.media3.extractor.text` 里查不到 BOM 处理（无 `Decoder`/`NulTerminatedCodec`，`SubripParser`/`SsaDecoder` 字节码里没有 `FEFF`），拿不准就让 `[Script Info]` 顶着 U+FEFF 去 `startsWith`，风险大于省一个副本文件；`SubtitleCharsetTest` 的 BOM 用例保持原判。**效果目前只有单测**（真机缺同名外挂 ASS / GBK / BOM 素材）→ **B21**。

### A4　切集后字幕不再挂上　P0

`SubtitleConfiguration` 只在 `applyQueue` 里写给当前下标那一项。自动连播走 `onMediaItemTransition` 时，从该项的 `subtitleConfigurations` 读回来是 null。`setSubtitle` 的业务调用只有全新装载和用户手动选文件。`observeEngineIndex` 只调用了 `restoreAudioMode`。`selectQueueIndex` 的快路径把字幕 uri 置成 null。

连播或选集跳到第 2 集之后，第 2 集记忆过的字幕、同目录同名自动匹配全部失效，只剩内嵌轨。

有记忆字幕的起播还会装两次。`session.open()` 只启动异步探测就返回，紧接着 `setSubtitle`。若此时装载已经完成（缓存命中时几乎是立刻），`canRemountCurrentItem` 为真，`replaceCurrentSubtitle()` 用整表 `setMediaItems` + `prepare()` 把刚建好的队列拆掉重来。缓冲清零。若探测比字幕准备慢，则走另一条分支，由 `applyQueue` 烘上。同一次点击，两条路径。

字幕作为 `open` / `setQueue` 的参数。第一次建表就带上 `SubtitleConfiguration`。`setSubtitle` 只服务已经稳定播放之后的用户更换，并且优先 `replaceMediaItem`，不要整表重设。

切下标的两个落点（观察引擎下标、`selectQueueIndex`）按该集的记忆和同目录匹配再解析一次。和仅听模式的恢复放在一起。

同目录匹配只查 `MediaStore.Files`，靠 `relative_path`。SAF 授权目录、`.nomedia`、不在媒体库索引里的文件匹配不到。本应用的主力就是授权目录扫描。对 `content://` 和 `file://`，用 `DocumentFile` 或 `File` 在同级列出字幕扩展名，和 MediaStore 并行，谁先命中用谁。

字符集探测的候选窄，结果用户看不见，也不能手动指定。探测失败时给出一次「编码可能不对」的提示，并允许选字符集。这是 P2，不要和 A3 的扩展名修复混成一次大改。

> 落地订正（2026-10-15，E138）：**主体已修**——`PlaybackSession.restoreSubtitle(item)` 挂在切下标的两个落点（`observeEngineIndex` 与 `selectQueueIndex`），姿势照 `restoreAudioMode`：改序号 → IO 读该集记忆 → 没有再走同目录匹配（命中即写回）→ 转码 → **两段各核一次条目身份**再挂。引擎侧照旧"新一集不继承上一集"，恢复归会话层。**上面四条改法里剩下的**：①「字幕作为 `open`/`setQueue` 的参数、第一次建表就带上」没做——起播路径仍是 `session.open()` 之后 `setSubtitle`，所以"探测先落地 → `replaceCurrentSubtitle` 整表重装"那两条路径**依旧同在一击之下**；②「`setSubtitle` 优先 `replaceMediaItem`」没做（文件里既有注记说它对当前项外挂字幕经常不重新挂上，换它要先真机验），于是**该集有记忆字幕时切集会多一次 rebuffer**，耗时未测；③`DocumentFile`/`File` 与 MediaStore 并行的同目录匹配没做，SAF 授权目录仍匹配不到；④字符集手动指定未动。**效果全部只有单测** → **B21**。

### A12　ASS 被压成纯文本　P1

`Cue.toKernelCue()` 在文本分支写的是 `SubtitleCue(text = text?.toString())`。media3 的 SSA 解码器已经把粗体、斜体、颜色放进 `CharSequence` 的 span，过这一行就没了。内核的 `SubtitleCue` 只有文本、位图、位图用的 `placement`。

`SubtitleLayer` 把所有文本 Cue 放进底部居中的一列，底边距大约 56dp，阴影写死，行高大约 1.3。只有位图 Cue 使用 `placement`。所以就算先不恢复 span，顶部对齐、双语上下分置的字幕也会被画到底部，叠成一列。竖屏视频区只有两百多 dp 时，固定 56dp 会把字幕顶到画面中部。一条很长的单行会占满高度。同一时刻十几条 ASS 对白会叠成字墙。

用户样式只有开关、颜色、倍率、斜体。没有描边、背景条、垂直位置、行距。白底画面上只有软阴影，读不清。

分两期，不要绑在一起。

第一期：按 Cue 已有的对齐和主色摆放。缺省才是底部居中。`\pos`、卡拉 OK、旋转做不到就提示「此字幕含特效，当前只显示文本」，不要假装已经支持 ASS。样式上加垂直位置、背景、描边、最大行数。这些不要等富文本。

第二期：`SubtitleCue` 携带 span，或在边界转成 `AnnotatedString`，并带上 line、position、anchor。`toKernelCue()` 不再 `toString()`。用户颜色叠上去，不要覆盖 ASS 里已经解出的颜色。

字幕偏移保持五个绝对档和 ±1 秒钳位，直到 A23 的时间窗修完。不要在窗口还是 250ms 误差时把上限放宽，±0.1 秒现在几乎看不出来。偏移不按媒体落盘。窗口修完之后，若要按媒体记住，单独落盘，不要靠会话里的残留。

内嵌弹幕和字幕是同一批 Cue。选了内嵌文本轨给弹幕时，`SubtitleLayer` 和弹幕层一起画。用户会看成字幕关不掉，或同一句出现两次。选了内嵌弹幕轨，就不要再把同一批 Cue 交给字幕层。外挂字幕和文件弹幕互不干扰。在有独立弹幕时间轴之前，这是唯一正确的互斥。

### A29　弹幕　P1

关掉弹幕之后，`LaunchedEffect` 的 key 里没有 `enabled`，仍会读完整文件、按 GBK 和 UTF-8 各解一次、解析、全量排序。热门片的 xml 或 ass 有上万条，和起播抢同一块存储。`enabled` 放进 key。关着就不要读。

帧循环只看「开关开着且有内容」。暂停时不写绘制用的帧状态，所以不一定重绘，但 `withFrameNanos` 仍每帧唤醒，并在暂停分支里重新锚定。暂停、缓冲、小窗退出这个循环。seek 已有位置收集，补一帧即可。计划结果是 0 条时，按延迟退避，不要逐帧转。

`TextWidthCache` 在 `textSizePx` 变化时整表清空。B 站 xml 和 ASS 每条自带字号，25 和 36 交替时缓存等于没有。键改成文本加字号，上限大约 4096 保留。

密度上限用 `takeLast`。窗口按时间升序，留下的是最晚出生的 N 条，更早、仍在屏幕中段的被丢掉，表现为闪断。滚动、顶部、底部共用一套轨道计数，会叠在同一行。改成丢掉尚未出生的，或按时间从早到晚保留仍应在屏上的。三种模式分三套轨道。

轨道号用窗口内序号取模。窗口起点随播放位置变，同一条在相邻帧可能换轨，seek 之后整列跳。用文件内稳定序号。加上轨道占用到何时，被占的轨不要再塞。

内嵌通路的 `spawned` 不保证时间升序。倒退 seek 之后二分会切错窗口。seek 时按新位置重建，不要只追加。

文件读取没有上限。字幕有大约 8MB 的有界读取，弹幕是 `readBytes()`。选择器接受任意类型，误选一个大视频会 OOM。用同一套有界读取。超限就提示来源不可用，不要静默继续。

ASS 弹幕的注释写 `\move` 当成滚动，代码里没有这个匹配，只是兜底成滚动。`Format:` 行只要含 Start 和 Text 就会覆盖字段表，不限在 `[Events]`。`Dialogue` 的段数和字段数不一致就整行丢。解析结果可以是空列表且没有原因。只在 `[Events]` 里认 `Format:`。段数不一致时，最后一个字段合并剩余文本。空结果要把原因传到 UI。

按集匹配只有「去扩展名之后全等」。`[狐妖] 第1集.mp4` 匹配不到 `EP01` 或「第 1 话」。文件名富化已经解析出集号，用标题和集号生成候选名。在线弹幕不做。

屏蔽词只作用于文件来源，内嵌轨不过滤。两种来源都过同一份屏蔽表。

### A30　截图　P1 / P2

API 26–28 上保存必然失败。写相册需要 `WRITE_EXTERNAL_STORAGE`，清单里没有，异常被吞成「截图保存失败」。minSdk 覆盖的 Android 8 和 9 因此不能用。要么在这些版本上声明权限并在运行时申请，要么改写到应用目录再插入媒体库，不要吞掉原因。

`getBitmap` 在主线程上取整块 TextureView，分辨率等于 View，不是片源。适应模式包含黑边。镜像和 180° 写在 View 的 `scaleX` / `rotation` 上，不在纹理里，所以镜像的片子截出来是正的。字幕和弹幕是叠在上面的 Compose，不会进照片。

产品含义定为画面帧，不是屏幕合成。toast 写「已保存画面」。按当前宽高比裁掉信箱。镜像和旋转若用户打开了，画面帧要带上，否则和正在看的方向相反。弹幕不要画进相册。字幕不要在这一轮叠进去。小窗和锁定态不要截。`FLAG_SECURE` 优先于截图，开着就不能截。

API 29 以下没有 `RELATIVE_PATH` 时，不要落在 Pictures 根目录。用媒体库能接受的子目录，或应用目录再插入。SurfaceView 如果以后换上，用 `PixelCopy`，不要只接受 `TextureView`。

### A31　睡眠　P1

播放页是两态：开等于从现在起 30 分钟后暂停，再点等于关。`toggleSleepTimer` 把到期时刻设成现在加 30 分钟，协程却是 `delay(30 * 60_000)`。进程被冻结后 `delay` 会停，墙钟不会。回到前台时，文案可能已经归零，暂停却还没发生，或者相反。

仅听页注释写这一格本是睡眠定时，能力尚未落地，实际画的是不能点的「后台播放中」。同一会话，两个界面各说各的。

到期时刻写入会话，并写入 DataStore。等待改成睡到 `endsAt`，醒来若还差就再睡。回到前台或进程重新起来时，若 `now >= endsAt` 立刻暂停。不要用一个固定 30 分钟的 `delay` 扛过 Doze。

档位四档：15 分、30 分、60 分、播完当前。两页共用同一个到期时刻。仅听页用现在的芯片位接上，去掉那行不能点的状态。到期只暂停，不要停会话，不要清队列。

倒计时不要在组合期读 `System.currentTimeMillis()`。A6 修好之后，这个「还剩 N 分」会停在打开那一瞬间。放进只画这一行的叶子，用对齐到分钟的 `delay`，和状态栏时钟同一套，不要 1 秒一拍。

### A32　章节和入口　P2

章节数据已经从 metadata 进来，菜单能跳。进度条仍是一条均匀的轨。`NpSeekBar` 的参数里没有章节。有章节时在轨上画刻度，点击刻度等同 `seekTo(startMs)`。没有章节不要画假刻度。不要为了刻度改拖动手感。面板头部加上一章、下一章。打开时滚到当前章。

截图、比例、字幕、睡眠都要先打开菜单再进子页。不要再加一条底部工具条把播放条挤矮。睡眠剩余时间可以出现在控制层已有的状态位上，和倍速不是 1x 时的提示同一重量。

「变速保持音调」在菜单里是一行不可点的说明。引擎只传 `PlaybackParameters(speed)`。服务侧已经 `setEnableAudioOutputPlaybackParameters(true)`，pitch 恒为 1，也就是保持音调恒开且不能关。要么做成真开关 `setSpeed(speed, preservePitch)`，要么把文案改成陈述句，不要用菜单行的样子假装有勾。

设置页「默认字幕语言」和「音频输出」是只读行，副题写即将支持。这不是假开关，代码写明了只展示。但「即将支持」是承诺。字幕语言要么从当前文本轨的标签读出真值，要么先撤下。播放页里「移除」那一格在删除还没接上之前不要出现，不要用危险色加一个只 toast 的按钮。

横屏全屏菜单没有文件详情，也没有「允许屏幕截图」。字幕颜色、大小、斜体只在播放页里能改，设置页没有。全屏菜单加详情页，主页加截屏开关。设置页加字幕区块，复用播放页已有的四个写入。截屏开关的说明包含「开启后不能画中画」。

## 10. 已定决定与不要再做

这些已经成立，或是明确的产品决定。不要重新开成任务。

- 回桌面、退后台自动进小窗。`onPictureInPictureRequested` 返回 true 并且不进入，是这条决定的一部分，不是死代码要「修活」。
- 恢复 `DecoderManager`。让 Legacy 无条件认领全部 `video/mp4v-es`。
- 删除 `libnplegacy`，或把 WMV2/ASP 并进 NextLib 只为少维护一份 FFmpeg。
- 把日常切集从 `seekToDefaultPosition` 改回整表 `setMediaItems`。队列已经挂上、且不是失败终态时，快路径已经是 seek。整表重装只留在失败终态，或控制器里还没有这份队列时。封面只在 IO 上取，并且只给当前项。
- 预载窗口整表重加。差集增删是为了避免孤儿预载源。缓冲中 seek 停住的问题不要用整表重加来修。
- 拆掉进程内的探测缓存、邻域预探测、探测的取消。要补的是负结果不要进缓存，以及 `Playable` 要不要落盘。
- 把 `npMotion` 以外的弹簧再暴露成 public。漏网的调用点改走 `npMotion`，不要新写时长表。
- 仅听页进度、内嵌右栏进度、迷你条时间码，这些重组域已经拆过。黑胶的旋转时钟不要改成从头转的无限过渡。
- 播放中降档改成订阅 `positionMs`。它只订「正在解视频」这一个布尔。仅听页因此进不了 `forPlayback()`，波形降档在仅听页单独做。
- 竖滑亮度、音量在值没变时仍打 binder。已经收过。
- 六档倍速、全宽播放条、条底不透明、全局不做 backdrop blur。
- 自写 PGS 解码器。做音频偏移。做流媒体。做在线歌词。做弹幕联网。
- 把个人页的跨 Tab 通道加回来。当前是 Tab 内的二级页，跨 Tab 会让底部条的选中态跳走。
- 音频焦点和拔耳机暂停。`setAudioAttributes(..., handleAudioFocus = true)` 和 `setHandleAudioBecomingNoisy(true)` 已经开了。
- 位置在播放页顶层解包。这一半已经守住，守不住的是缓冲和 Cue，见 A6。
- `OwnedSurfaceCloner` 的换表面先释放、重复释放幂等。输出缓冲在 `finally` 里 release。软解输出模式能传到解码器。AVI idx1 的三种基准都试过。WMV2 extradata 从 `BITMAPINFOHEADER` 之后切，和奇数尺寸的怪例。MPEG-4 VOL 的字段顺序。ASP 改写和探测共用一个闸门函数，不要再抄一份。封面读取有上界。扫描的 LIKE 已转义。插件按依赖拓扑排序，环和缺依赖会失败。这些不要再当缺陷报。
- 快照写 `.tmp` 再 rename 这个姿势成立、保持。**但 rename 失败仍先 `delete()` 旧文件那一支不在豁免内**——那是 A33。
- `OwnedSurfaceCloner` 的 `release()` 幂等、以及设置新 Surface 时释放旧克隆（从 A19 移来；A19 只剩 `Log.w` 加一条用户可见诊断）。
- 探测缓存的命中键已经带 `sizeBytes + lastModifiedSec` 指纹，`prepare` 与详情页进全屏这条主入口**会**读写缓存（A20 已订正，别再按旧写法去补传参）。
- 日常切集的快路径 seek 已经成立（A15 订正）；`AviDurationTest` 已经是按字节构造 `avih`/`strh` 的 JVM 夹具（A20 订正）。
- 倍速文案已收成 `speedLabel` 一处，`removeSuffix("x")` 死代码已清（A6 订正）。
- 离开类 PC 档那一帧右栏是**当场拆**，不等宽度动画（`paneShown`）。这是真机逐帧取证的结论（一层大一层小的两个视频实例叠在半透明页上），别改回「让动画收完」。
- 转屏交接走整屏 morph（`NpMorph` / `NpPlayerPose` / `NpFormHandoff` 的一次性时限标记），抓帧黑幕层已删。系统 3D 旋转动画本身在这台 HyperOS 平板上不被采纳（`ROTATION_ANIMATION_JUMPCUT` 无效），**属系统边界不是缺陷**；换 EMUI / ColorOS / AOSP 设备要重拍，与"morph 的真机动效至今没拍"同一笔账，**挂 B20**。
- 「竖屏播放页 → 横屏交还右栏」在设置「后台播放 = 关」时会随 `onDispose` 走一次 `stop()`，沿用返回键的既有语义——这是既定语义，不是新缺陷；只是还没在该开关下复拍，挂 B1。
- 用户在「我的」Tab 里看视频再转横屏，左栏仍是「我的」+ 右栏画面：`NpDetailRequest` 只由媒体库消费，**不替用户切 Tab**（切 Tab 正是被驳回的动作）。不要加回跨 Tab 通道。
- 外挂字幕的**容器格式由认得文件名的一侧显式传给引擎**（`NpSubtitleFormat` + `setSubtitle(uri, format)`，`SubtitleFile` 从 `DISPLAY_NAME` 判）。不要再退回"从 uri 末段猜"——MediaStore 与 SAF 的 uri 末段是 id，猜出来永远是 SubRip。转码副本的扩展名取自格式白名单，不是用户文件名上的任意串。
- `PlaybackState` **没有 `Ready` 这一态**（E138 已从契约删除）：`STATE_READY` 在映射处就按 `playWhenReady` 落成 `Playing`/`Paused`。不要为了"装载完但没播"再引入一个就绪态——那个需求由 `Paused` + `playbackStarted` 承担。
- 小窗（PiP）动作按钮的 PendingIntent 归**引擎**给（`VideoPlayer.mediaButtonIntent`），UI 只贴图标文案、拿不到通路就不画。不要在 UI 侧自造 `PendingIntent.getService`。
