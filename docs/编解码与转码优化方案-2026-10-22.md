# 编解码 · 格式拓展 · 内置转码 —— 优化方案（最终版）

版本：v2（2026-10-22）　状态：**已按源码评审收口**
基线提交：`731474a perf(player): E170 —— A19 原生平面池与 4 帧背压`
release 体积基线：**19,654,677 B**（E167 / B19，`docs/任务文档.md:39,290`）

---

## 0. 摘要

本方案回答三件事，并按"投入产出 + 风险"排序给可执行条目：

1. **内置转码怎么做**：先做受能力矩阵约束的 P0/P1/P2，不承诺所有当前播放器输入都能转。第一期只接平台能读取、能解码、能编码且目标容器能接纳的轨道；不把现有 Exo renderer 当成离线转码器。
2. **编解码性能怎么提**：先做格式级能力求交和可复现基准，再做 SIMD 和帧桥优化；不把“删除几个 configure 开关”直接写成 2–5 倍收益。
3. **格式拓展怎么扩**：先补真实需求最高的容器/编码组合，再评估 FFmpeg demuxer。B2 仍优先于 B3，但不在转码一期并行引入；第二引擎保持最后选项。

**本版重点是 §6.6 的决策收口、§6.8 的分期边界与 §13 的最终路线。** 仍保留明确的"未证"项（§12），其中天玑机上 `libnplegacy`、MPEG-4 ASP、NextLib 的真实加载能力不能作为转码一期的前置假设。

## 6. 内置转码方案

### 6.1 边界（本次明确）

做：受能力矩阵约束的**提取/转封装/视频转码**。
不做：**音频→音频互转**（唯一例外见 D-1）、**字幕烧录**（hardsub 是独立功能）、在线源。

### 6.2 核心决策：一期走平台，但不覆盖全部现有输入

用 `MediaExtractor`（读）+ `MediaCodec`（解/编）+ `MediaMuxer`（写），**零新增 native**，但只对平台三件套实际支持的来源和目标组合开放。当前应用还有 Media3 自定义 AVI extractor、`video/x-np-*` legacy renderer 和 MJPEG 位图 renderer；这些不是 `MediaExtractor`/`MediaMuxer` 自动接管的输入输出，不能把“平台路线”写成全格式通转。理由：

- 两台机器都有 HEVC 硬编且支持 CQ（§2），硬编吞吐与能效远高于任何软件路线；
- release 基线 19,654,677 B 里 native 占大头，为转码补 FFmpeg `avformat`+encoder 会按 ABI 翻倍膨胀（§10 红线一），并触碰 GPL 边界；
- `MediaMuxer`/`MediaExtractor` 是系统基础设施，但具体 codec、profile、容器接纳仍要按 API、设备和实际 `addTrack`/`configure` 结果闸门判断；它们只能作为一期的可靠地基，不能替代能力探测。

### 6.3 能力闸门（方案的承重墙）

新增 `CodecCapabilitySnapshot`：生产路径先做**进程内、按具体 Format + 候选 codec 的实时判定**；DataStore 只保存带 `Build.FINGERPRINT`、API level、codec 列表摘要和应用版本的加速缓存，任何命中都要在关键 `configure`/`addTrack` 前复核。内容包括每个候选 encoder/decoder 的 `profileLevels`、`videoCapabilities`（宽高/fps/码率区间）、`isBitrateModeSupported`、`concurrent-instances`、是否声明 Surface 输入。
实现口径照抄现成的 `Mp4vAspGate.kt:89`（"问 `findDecoderForFormat` **真正会选中的那一个**"）与 `PlatformDecoderSupport.kt:187`（能力快照），把只覆盖 decoder 的现有逻辑复制到 encoder 侧。**绝不按组件名前缀（`c2.qti` / `c2.mtk`）匹配。**

### 6.4 三个动作，按来源能力分流

**动作一：提取音频（先做，最便宜）**
`MediaExtractor` 选音轨 → 仅在目标容器明确接纳该 codec 时 **stream copy**。一期先收 AAC→MP4/M4A、Opus→WebM；MP3 不假设可装进 MP4，先保持原始 `.mp3` 提取或列为未支持。**不在一期偷偷把 Opus/MP3 重编码成 AAC**，否则越过“音频互转不做”的边界。

**动作二：通转**
默认目标 MP4(`avc1` High + `mp4a` AAC-LC)只对“视频可转、音轨可直接复制”的输入开放。路由规则：**先做静态能力闸门，再尝试 `addTrack`/`configure`；不满足就明确失败**。一期不因视频转码自动触发音频重编码；音轨不兼容时改选 WebM/原容器，或让用户取消。

**动作三：视频互转**
仅对平台解码器/编码器链路做视频转码：解码器输出 Surface 直接接编码器 `createInputSurface()`，通过独立的 MediaCodec 管线驱动，不复用 ExoPlayer 播放时钟或 renderer。码控优先 `BITRATE_MODE_CQ`，但必须逐 codec 探测，缺失则退 VBR；≥1080p 的 HEVC 只作为用户选择且经过 profile/尺寸/码率/温控闸门。默认不降分辨率、不改帧率，但遇到能力不足要失败并说明原因，不自动改变用户语义。

**分档表**

| 档 | 动作 | 覆盖 | CPU/耗时 | 风险 |
| --- | --- | --- | --- | --- |
| P0 | 音轨 copy 出 `.m4a`/`.webm` | AAC/Opus 首批；MP3 单独提取或暂不支持 | 秒级 | 低，但以目标容器实际接纳为准 |
| P1 | remux（视频流 copy + 换容器/挑轨） | 按 API/容器矩阵开放；MP4 与 WebM 分开，不承诺 MKV | 秒级 | 低，但必须以 `addTrack` 实测接纳为准 |
| P2 | 硬编转码（Surface→Surface） | 平台能解能编的 | 待固定设备/素材基准 | 中（thermal） |
| P3 | 专用帧桥（后续，不是 Exo renderer 复用） | MJPEG / `x-np-*` legacy 轨 | 慢（软解） | **暂不排期**，需独立 YUV/Bitmap→编码 Surface 桥 |

### 6.5 P3 暂不复用现有 Exo renderer

MJPEG 走 `BitmapFactoryVideoRenderer`、WMV2/ASP 走 `LegacyVideoRenderer`——它们是 renderer，不是可供离线转码直接消费的 `MediaCodec`。当前 `LegacyVideoRenderer` 最终调用 `LegacyNative.nativeRender`，而 native 路径对目标 Surface 做 `ANativeWindow_lock` 并写 CPU RGBA；编码器的 `createInputSurface()` 不能假定支持这条 CPU producer 连接。用 ExoPlayer 把“播放输出 Surface”直接当“编码输入 Surface”还会遇到节拍、丢帧、EOS/PTS 和 Surface producer 连接问题。

后续若确有需求，单独做 `FrameSource`：legacy 输出 YUV、MJPEG 输出 Bitmap/像素，再用 GLES/EGL 或受控 native 色彩转换写入编码 Surface；同时补逐帧计数、PTS、EOS、颜色矩阵和取消回收测试。必须继续遵守 `OwnedSurfaceCloner` 的播放 Surface 连接归还约束，但不能把它当成 P3 已解决的依据。

### 6.7 工程落点（沿用现有规矩）

## 10. 红线与风险

1. **体积基线是硬约束**（即使本稿假设"不限体积"）：E167 刚把 release 从 41,864,391 收到 **19,654,677 B（−53.1%）**，手段就是砍 ABI。任何新增 .so 都要 **×2 个 ABI** 记账，并重新拍 B19 基线。**因此 §6 的转码方案刻意做到零 native 增量**——这条必须在评审中被当作不可协商项确认或明确豁免。
2. **许可证边界**：NextLib 本体 **GPL-3.0**、其捆绑 FFmpeg **LGPL-3.0 且未开 `--enable-gpl`**（`libs.versions.toml:31-34`）。**不要为了转码引入 x264/x265（GPL）**，否则义务面从"动态链接 + 声明"扩大到整体组合作品的开源义务。`docs/decoding/extension-decoder-decision.md:40,67` 的"许可证待核"应在动 B1/B2 之前先关掉。
3. **进程内约束**：`NpRenderersFactory` 的 PreloadManager 双次调用约束（§3）同样适用于转码管线——**工厂构造期不得 `System.load`**、不得产出两次渲染器集合。`DecoderManager` 运行期切换依旧禁用。
4. **Surface 连接归还**：`OwnedSurfaceCloner` 解决的是实测过的 `connect: already connected` 崩溃类问题。A3/P3 任何改动碰到 CPU 渲染都必须保留它。
5. **0 字节 / 截断项**：天玑机实存 1 个 0 字节 mp4。转码若以它为目标会写出空产物；扫描阶段就该按"长度 < 容器头"判不可播（扩展 `ScanFailureMemo` 的覆盖面，E166）。
6. **thermal**：两台机器并发余量宽，但热降频会让 3–8× 实时变成 <1×。P2/P3 必须监听 thermal 并退队，不能硬扛。

## 13. 最终优化方案（本次源码评审结论）

### 13.1 必须先改正的原稿结论

1. **平台三件套不是全格式转码器**：当前 AVI/WMV2/ASP/MJPEG 有 Media3 自定义 extractor 或自有 renderer，不能仅用 `MediaExtractor` 读取，也不能让 `MediaMuxer` 自动接上 `video/x-np-*`。
2. **P3 不能直接“Exo 播放到编码 Surface”**：`LegacyVideoRenderer → LegacyNative.nativeRender → ANativeWindow_lock` 是 CPU producer 路径，不等于编码器 `createInputSurface()` 的 GPU 输入路径；还存在播放时钟、丢帧、PTS/EOS 和连接归还问题。P3 必须另做帧桥，当前不排期。
3. **“MP4 + AAC”与“不做音频互转”不能同时作为默认承诺**：Opus 选择 WebM 原样 copy；MP3 不假设可进入 MP4；视频转码一期不自动把音频重编 AAC。
4. **能力缓存不能只按 MIME 或 `Build.FINGERPRINT`**：必须按具体 Format、profile/level、位深、尺寸、帧率、码率和真实候选 codec 判定；持久化快照只能作加速缓存，不能作正确性依据。
5. **A1 的 2–5×、T3 的 ≥3× 不是当前证据**：先基准、后改配置；性能结论按 ABI、设备、分辨率、码率、温度和电量记录。

### 13.2 施工顺序

| 阶段 | 只做什么 | 明确不做 | 退出条件 |
| --- | --- | --- | --- |
| R0 能力与素材基线 | 导出两台设备实际 decoder/encoder 能力；准备 AAC/Opus/H.264/HEVC Main10/AV1 与 0 字节、截断、大文件夹具；建立首帧、转码速度、温升、包体基线 | 不改播放链，不先写 UI | 快照含 API/设备/codec 名/profile/level/尺寸/码率/Surface/并发；缺证据项标 blocked |
| R1 音频提取与 remux | 仅做 AAC→M4A/MP4、Opus→WebM；按 `addTrack` 和实际 muxer 结果验收；失败原子清理 | 不做音频重编码；不承诺 MKV/MP3→MP4 | 复制后样本数、时长、首尾时间戳和播放结果一致 |
| R2 平台视频转码 | 独立 `MediaCodec` 解码器→编码器 Surface 管线；音频仅复制兼容轨；CQ→VBR 有界回退；Room 作业、取消、恢复、MediaStore `IS_PENDING` | 不复用 Exo 播放时钟/renderer；不接 legacy/MJPEG | 固定设备/素材下帧数、PTS、EOS、关键帧、产物可播、取消无残片 |
| R3 性能优化 | A4 格式能力求交；A1 SIMD A/B；A2 先量 JNI/内存拷贝再设计 native/GLES 路径；A8 首帧埋点 | 不凭经验承诺倍数；不直接把 CPU `ANativeWindow_lock` 接编码 Surface | 两 ABI、两设备的收益/体积/温升记录满足门槛 |
| R4 扩展格式 | 按真实需求选择 B1 白名单或 B2 FFmpeg demuxer；单独评估许可证和包体 | 不与转码一期并行引入 `avformat`；不先引入第二引擎 | 至少一类真实缺口有容器、轨道、seek、字幕、失败恢复闭环 |
| R5 legacy/MJPEG 转码 | 只有在需求和样本足够时实现 `FrameSource` + GLES/EGL/native 色彩桥 | 不用 Exo 离屏播放作为替代实现 | PTS/EOS/颜色/stride/取消/Surface 连接全有自动与设备证据 |

### 13.3 最终产品范围

- **一期交付**：AAC/Opus 无损提取、受矩阵约束的 remux、平台可解可编的视频转码、单并发可取消作业、错误面板快捷入口和作业列表。
- **一期明确不交付**：音频互转、字幕烧录、MKV 作为 `MediaMuxer` 目标、AVI/WMV2/MJPEG 的“自动通转”、faststart 保证、后台进程被杀后的无条件续跑。
- **保留为后续研究**：A1 SIMD、A2 帧桥、B1/B2 容器拓展、C1–C4 画质/字幕能力；每项必须先有素材、设备和体积/许可评估。
