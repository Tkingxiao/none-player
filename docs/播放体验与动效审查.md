# None Player 播放与界面体验审查

> **目的**：对照现代本地/在线视频播放器（包括 B 站等产品的常见交互习惯），检查全屏播放器、菜单/弹层、浏览窗口、动画、手机/平板/窗口化显示中的“第一直觉”偏差，给出可复核证据与修正建议。本文是**代码审查/设计体验记录**，不是声称已在所有设备复现的 bug 清单。
>
> **审查范围**：项目 `None Player` 的播放器播放栏与手势、播放菜单、弹幕/字幕、媒体库/搜索页、导航与外壳、手机/平板横竖屏/类 PC / 自由窗口。 
>
> **审查方法与边界**：当前轮只读 Kotlin/Compose 源码及项目内文档；没有连接运行中的应用进行截图走查、没有本轮编译/测试、没有设备或模拟器复现。凡“代码可确认”指源码能直接说明当前行为或结构；凡“边界风险/待设备验证”不得当作已复现故障。项目已保存的旧截图、审查记录属于**历史证据**，不代表本轮重新验证。
>
> **引用规则**：下文相对路径均从仓库根目录 `None Player/` 起算。已有设计规格、已知取舍与本轮新发现分开标记。优先级是建议顺序，不代替项目任务文档的既有优先级。

## 1. 一眼结论

项目并不是缺少播放器功能或动画。它已经有明显完整的架构与规格：全屏控制层显隐、seek / 缓冲段、倍速、菜单锚点、字幕与本地弹幕挂载、音频模式、窗口形态分派、Reduced Motion、标签与路由过渡都有相当多实现。真正值得继续排查的是：**不同操作是否使用同一套一致逻辑、入口是否易发现、窄窗口是否能容纳、浮层之间是否互斥、模式跨来源后是否仍正确、项目规格与代码是否真的同值，以及动画是否在每个状态转换都存在而不只是“某处有动画”。**

### 本轮确认级别概览

- **源码可确认的功能/逻辑问题**：搜索 `.` 匹配全部；搜索输入与结果短暂错代；来源 ID 命名空间在历史映射处被去掉；锁定态清理弹层不完整；倍速两套入口档位不同；几类按钮/控件语义或可发现性薄弱；全屏菜单子页直接替换、文件信息卡缺入退场。
- **布局 / 体验风险，需具体窗口设备验证**：菜单在矮窗口夹高、搜索结果头部挤压、子文件夹与视频错峰重复计序、字幕与底栏覆盖安全区、可调窗口临界宽度切换、焦点弹窗键盘、静态图片无法在代码审查中判断真实裁切。
- **历史记录中已声称修复或明确取舍**：不要重复当成“当前必然缺陷”。参考第 9 节与仓库根目录《审查文档.md》《任务文档.md》。这些记录本身还保留未验设备项；本轮不为它们背书，也不反向推断缺陷仍在。

### 2.2 新发现及需重点确认的问题

#### P1 · 搜索只输入一个点会返回全媒体库

**证据等级：代码可确认；触发条件明确。** 扩展名匹配先对查询执行 `removePrefix(".")`，随后对扩展名调用 `contains()`；当 query 正好是 `.` 时，比较串变成空字符串，`contains("")` 对每个扩展名都为 true。即便标题/目录均不匹配，所有媒体也会命中。

证据：[SearchScreen.kt:137-153](../None Player/plugins/plugin-library/src/main/kotlin/com/noneplayer/plugins/library/SearchScreen.kt#L137-L153)，尤其 150–152 行。

**修正建议**：仅在去掉前导点后的扩展查询非空时做 extension 分支；单元测试覆盖 `"."`、`.mkv`、`mkv`、空查询、名称本身含点等情况。

#### P2 · 输入框与结果使用不同版本的搜索词，刚打完字时可打开旧结果

**证据等级：代码可确认的短暂状态错位。** 输入值 `query` 立即更新，但结果由 `debouncedQuery` 驱动，等待 120ms 后才同步；这段时间结果区仍是旧关键词结果，而点击回调会把当前新 `query` 写入搜索历史，却打开旧结果中的媒体。

证据：[SearchScreen.kt:116-126](../None Player/plugins/plugin-library/src/main/kotlin/com/noneplayer/plugins/library/SearchScreen.kt#L116-L126)、[SearchScreen.kt:137-163](../None Player/plugins/plugin-library/src/main/kotlin/com/noneplayer/plugins/library/SearchScreen.kt#L137-L163)、[SearchScreen.kt:205-223](../None Player/plugins/plugin-library/src/main/kotlin/com/noneplayer/plugins/library/SearchScreen.kt#L205-L223)。

**修正建议**：在 `query != debouncedQuery` 时显示短暂加载态、禁用旧结果点击，或让结果项绑定其生成时 query snapshot 并以同一 snapshot 记历史。不要让用户在“输入是 A、结果属于 B”的视觉状态下确认选择。

#### P1 · 历史进度按裸 `mediaId` 汇总，可能跨来源串进度/最近播放时间

**证据等级：跨来源 ID 冲突时源码必然串值。** 历史模型的唯一媒体键明确为 `sourceId:mediaId`，但媒体库进度和最近播放时间 map 用 `mediaId` 当唯一键。不同 `MediaSourceProvider` 出现相同媒体 ID 时 `associate` 会覆盖同 ID 的另一条，继续观看比例、卡片进度、未看完筛选或“最近播放”排序可能用错记录。

证据：[LibraryScreen.kt:385-395](../None Player/plugins/plugin-library/src/main/kotlin/com/noneplayer/plugins/library/LibraryScreen.kt#L385-L395)、[HistoryEntry.kt:11-15](../None Player/core/database/src/main/kotlin/com/noneplayer/core/database/HistoryEntry.kt#L11-L15)、[HistoryEntry.kt:42-45](../None Player/core/database/src/main/kotlin/com/noneplayer/core/database/HistoryEntry.kt#L42-L45)。

**修正建议**：把进度/lastAt map 和全部查询点统一改为 `HistoryEntry.keyOf(item)`（`sourceId:mediaId`），避免只有持久化层有命名空间、展示层又退化成裸 ID。

#### P2 · 倍速入口看似同一功能，但竖屏/仅听和全屏可选档不一致

**证据等级：代码可确认。** 竖屏播放页与仅听页的横向 `SpeedChoiceRow` 只有 `0.5 / 0.75 / 1 / 1.25 / 1.5 / 2.0x` 六档；全屏锚定菜单含十档 `0.25–3.0x` 与 ±0.05 微调（可到 4x）。所以同一媒体在全屏调好 2.5x，退到竖屏后从倍速按钮看不到当前档所在项，也无法从快捷条直接选同档（虽然当前速度可能在胶囊/文字中显示）。这是为了给窄控件排布留空间的已知版式选择，但状态和动作能力跨形态不一致。

证据：[PlayerScreen.kt:235-251](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L235-L251)、[PlayerScreen.kt:3401-3439](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L3401-L3439)、[PlayerFsMenus.kt:608-647](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerFsMenus.kt#L608-L647)。

**修正建议**：横向条继续提供高频快捷预设，但加“更多倍速”进入完整相同选项；当当前速度不在六档内，显示真实选中值，不能让用户猜是哪档。项目全屏锚定菜单提供完整档位，因此可以让两个入口复用同一份档位/当前态渲染策略，而不强行把十档都塞进窄横条。

#### P3 · 倍速细调行的手感与边界反馈需设备确认（按点步进是既有设计，不是缺陷）

**证据等级：代码可确认当前反馈形态；手感需真机。** 倍速子页把 ±0.05 两个步进按钮与中间当前速度文本放在一行；当前值可见且非 1x 时着色，但这一步进没有触觉/即时提示，边界（0.25 下限 / 4x 上限）也没有专门反馈。

证据：[PlayerFsMenus.kt:608-647](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerFsMenus.kt#L608-L647)。

**判断修订**：项目明确把倍速细调设计成点按步进，并注释说明“长按不加速”是避免与长按 3x boost 冲突；因此“不支持长按加速”**不是缺陷**，保持按点步进属于有意设计。本条只建议设备上确认连续点按的手感和边界反馈，不追加长按重复功能。

#### P2 · 锁定态清理弹层有漏项，存在“锁住却仍留下可操作面板”的条件

**证据等级：状态遗漏代码可确认，实际叠层结果需输入路径验证。** 锁定副作用清掉 episode、fs 菜单、speed、subtitle、more、file info；但可独立打开的章节面板、音轨 sheet、画面 sheet、均衡器 sheet 没有在同一清理块关闭。若键盘 L 或其他路径可在这些层打开时切入 locked，播放页 `BackHandler` 会吞返回，而残留 sheet 本身仍处于组合树。

证据：[PlayerScreen.kt:1360-1375](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L1360-L1375)、[PlayerScreen.kt:1448-1484](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L1448-L1484)、[PlayerScreen.kt:775-778](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L775-L778)。

**修正建议**：统一 `dismissAllOverlaysForLock()` 将所有 sheet、panel、Popup 状态清空；设备测试路径：打开“音轨/画面/EQ/章节”→按 L 或其他锁定入口→检查是否只有解锁按钮可交互、Back/Esc 是否可恢复。

#### P2 · 竖屏字幕偏移控件的小目标可能难点中

**证据等级：代码可确认点击容器尺寸偏小；误触率待设备验证。** 四个 ±50/±250ms 偏移项只有文字上下 padding 10dp，没有 `heightIn(min=44dp)` / `npTouchTarget`；以 11sp 单行文字计算，目标高度小于播放器控件通用 44dp 基线，横向均分时也可能造成相邻项误点。

证据：[PlayerScreen.kt:2655-2675](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L2655-L2675)，对照 [`NpDimens.touchTarget=44dp`](../None Player/core/ui/src/main/kotlin/com/noneplayer/core/ui/DesignTokens.kt#L145-L167)。

**修正建议**：仅扩大透明 hit target，保持视觉尺寸/间距；检查四项区域不重叠、TalkBack 可识别并在窄窗里不换行。

#### P2 · 倍速胶囊与调速入口并存，更多菜单中的倍速动作与可见控件不匹配

全屏播放时非 1x 倍速会在左上角显示常驻状态 pill，设速入口在底栏速度图标；但“播放选项”中的“倍速”会切换 `speedPickerVisible=true`，而横屏全屏 `inlineSpeedRow=false`，所以该动作不会显示 inline 选择条，只会关掉更多 Sheet 并留下当前状态。全屏真实入口仍是底栏图标的 `FsDropdown`。源码行为可确认，用户是否误以为“点了没反应”需走查。

证据：[PlayerScreen.kt:4065-4083](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L4065-L4083)、[PlayerScreen.kt:2849-2854](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L2849-L2854)、[PlayerScreen.kt:1960-1972](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L1960-L1972)、[PlayerScreen.kt:3641-3658](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L3641-L3658)。

**建议**：更多面板的倍速动作在全屏时直接打开 SPEED 子页；竖屏时保持当前快捷条。状态 pill 只负责显示当前速度，不承担隐藏入口。

#### P2 · 全屏 ⋯ 菜单的子页切换有硬切，面板退场动画不是子页动画

`FsDropdown` 对 Popup 本身实现缩放/淡入退场，但 MAIN→SPEED/SUBTITLE/AUDIO 等只是 `when(page)` 直接换 Composable，没有 `AnimatedContent`/交叉淡化/横向 drill-in 转场。用户体验是菜单打开有动画、点“倍速/字幕”后内容瞬变，返回页同样突变，不符合整个选项层都优雅连续的目标。

证据：[PlayerScreen.kt:2002-2023](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L2002-L2023)、[PlayerFsMenus.kt:143-205](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerFsMenus.kt#L143-L205)。

**建议**：内部 page 以 key 驱动轻量 150–200ms fade-through + 8dp 来向位移；操作后退出仍复用当前独立 dismiss 动画；遵守项目已有 reduce-motion/token 管道。不要让面板装载/定位重新播放入场动画。

#### P2 · 文件信息卡 scrim 可点关闭，但卡片内容没有消费点击，误触内容也会关卡

卡片外层整屏 Box 带 `clickable(onDismiss)`，中间信息 `Column` 没有消费 click。点击任意标题/文件值等也会冒泡到 scrim 并关闭，用户可能正在选中文本/尝试复制时直接退掉；卡片也没有可见关闭按钮或“复制值”入口。

证据：[PlayerScreen.kt:3018-3045](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L3018-L3045)。

**建议**：卡片内容层消费点击并提供明确关闭钮；可复制的 URI/文件名提供长按复制或复制 affordance。卡片本身只有淡入/缩放? 当前其函数是静态 Box/Column，而共享 `npPanelEntrance` 仅被错误/结束态调用，故文件信息卡明确缺进退场动效。

#### P3 · 文件信息卡和章节/选集的出入动效覆盖不一致

错误/结束态使用 `npPanelEntrance`，`NpSheet`/FS dropdown 有专属 motion；`FileInfoCard` 直接条件挂载静态布局，遮罩与卡片都没有 AnimatedVisibility/scale/fade；EpisodePanel 是直接条件挂载且只有布局，没有独立进退场状态（其 `Surface` 本身也未用 sheet 进出动画）。

证据：[PlayerScreen.kt:3018-3080](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L3018-L3080)、[PlayerScreen.kt:3090-3095](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L3090-L3095)、[PlayerScreen.kt:3173-3265](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L3173-L3265)。

**建议**：覆盖层进入/退出共用 opacity + 小位移/scale token；关闭状态保留动画时长后再 dispose；打断时从 presentation state 接续，不能点击后整张面板瞬间消失。

#### P2 · 弹幕内嵌轨来源选择后阻断后续文件源切换，且没有退出内嵌轨的入口

`embeddedPicked` 非空时，文件来源重新加载 effect 直接 return；菜单可以保存/选择弹幕文件，却没有把 `embeddedPicked` 清回 null 的 UI 动作，所以先选中内嵌轨之后再选择文件，文件 URI 可写入但不会替换当前内嵌 source。这个行为也容易让“选择弹幕文件”承诺落空。

证据：[DanmakuOverlay.kt:119-136](../None Player/plugins/plugin-danmaku/src/main/kotlin/com/noneplayer/plugins/danmaku/DanmakuOverlay.kt#L119-L136)、[DanmakuOverlay.kt:290-329](../None Player/plugins/plugin-danmaku/src/main/kotlin/com/noneplayer/plugins/danmaku/DanmakuOverlay.kt#L290-L329)。

**修正建议**：来源采用显式 single-source state：自动/手动文件/内嵌/关闭；选新源时清理旧源并卸载；菜单呈现当前来源以及“恢复自动匹配/清除选择”。

#### P2 · 内嵌弹幕 cue 可能同时作为字幕渲染，重复显示同一行

当前内嵌弹幕通过 `player.cues` 生成滚动弹幕；相同 cue 仍会由 `VideoStage` 无条件交给 `SubtitleLayer`，所以屏幕上可能出现一份字幕固定底部、一份弹幕横向滚动。项目代码注释已把它列为已知限制，但这仍是用户看到的重复呈现，不应只当隐藏实现细节。

证据：[DanmakuOverlay.kt:74-77](../None Player/plugins/plugin-danmaku/src/main/kotlin/com/noneplayer/plugins/danmaku/DanmakuOverlay.kt#L74-L77)、[DanmakuOverlay.kt:154-163](../None Player/plugins/plugin-danmaku/src/main/kotlin/com/noneplayer/plugins/danmaku/DanmakuOverlay.kt#L154-L163)、[PlayerScreen.kt:4294-4307](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L4294-L4307)。

**建议**：分离 subtitle/danmaku track 的显示职责，或弹幕轨被选为滚动层时提供“同时显示原轨字幕”开关，默认避免双份。

## 3. 播放手势、触发区域与隐藏/恢复逻辑

### 3.1 当前实现（代码可确认）

- 舞台单击切换控制层；双击按横向三分区：左/右侧 seek，中间播放/暂停；横滑 seek；左 1/3 竖滑亮度，右 1/3 竖滑音量；中间 1/3 不处理竖滑。轴判定 threshold 10dp；两侧边缘 24dp 让系统返回手势，竖滑在上下 48dp 死区避让系统栏。
- 长按临时 3x，松手恢复。拖动 seek 时保持栏；播放持续且正常闲置约 3500ms 自动收起；缩放/弹幕入口均应与栏一起收起。
- 代码说明手势优先关系是“横滑 > 竖滑 > 双击 > 长按 > 单击”；拖动状态机与 `detectTapGestures` 分开接管。

依据：[StageGestureLayer.kt:13-52](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/gesture/StageGestureLayer.kt#L13-L52)、[StageGestureLayer.kt:54-163](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/gesture/StageGestureLayer.kt#L54-L163)、[PlayerScreen.kt:1112-1129](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L1112-L1129)、[PlayerScreen.kt:983-1004](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L983-L1004)。

### 3.2 体验风险与建议

1. **键盘快捷操作不统一唤回控制层**。Space、方向 seek、音量、M 静音动作处理后直接 return，没统一 `controlsVisible=true`；对比 L/F 等其他操作有显式显控层。鼠标/触屏自动隐藏环境里，键盘暂停后操作结果可能没有明确持久可见反馈。证据：[PlayerScreen.kt:1682-1702](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L1682-L1702)。**建议**：至少状态改变类操作唤回控件并重置超时；如为了沉浸而不唤回，应给稳定、非瞬时的操作 HUD。外接键盘实测。
2. **横向滑动 seek 按满屏宽度映射 ±90 秒**。相同手指距离在不同窗宽映射不同时间；120Hz/小窗中目标精度是否足够不明。证据：[StageGestureLayer.kt:34-35](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/gesture/StageGestureLayer.kt#L34-L35)、[StageGestureLayer.kt:143-147](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/gesture/StageGestureLayer.kt#L143-L147)。考虑采用分段速度/屏幕比例之外的稳定 dp 灵敏度，并显示 +/- 反馈；不是源码逻辑 bug，需真人比较。
3. **手势设置描述不全**：“启用音量/亮度手势”开关副标题说左右滑调节音量/亮度，但实际是竖滑调节、横滑 seek，关闭开关却通过 `gesturesEnabled` 关掉双击 seek/长按加速等全部舞台手势，不只是音量亮度。证据：[SettingsScreen.kt:457-477](../None Player/kernel/kernel/src/main/kotlin/com/noneplayer/kernel/SettingsScreen.kt#L457-L477)、[PlayerScreen.kt:1383-1402](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L1383-L1402)。这是清晰的文字-行为不匹配。建议将开关语义扩大为“启用播放手势”，或拆分亮度/音量与 seek/长按设置，并把副标题轴方向写对。
4. **中间单击仅切换控制栏，不播放/暂停；中心双击才播放/暂停**。部分播放器肌肉记忆会预期单击仅显控件，中间双击暂停；当前中心双击暂停属可配置习惯但不普遍，务必在帮助/手势设置中解释。优先保留单击唤栏避免触控误停。
5. **单击与双击存在系统等待窗口**。`detectTapGestures` 需等待双击可能延迟单击显栏。感知延迟需实测；可考虑单击立即显示（短延迟撤销/双击压制），但不要在未测前引入 tap/seek 冲突。
6. **边缘 24dp seek/竖滑不工作属明确手势避让设计**，不应误记成误触 defect；建议在短指南/设置帮助里解释边缘拖动留给系统返回。
7. **长按 3x 与平台长按菜单/选中文本直觉可能冲突**：仅视频画面区域承担 3x，弹层/控件独立操作；用户若反馈“长按画面不知为何加速”，给首次提示或设置开关，但不加常驻说明文字。

## 4. 菜单、弹层、弹幕与键盘焦点关系

### 4.1 全屏菜单现状

FS dropdown 是锚点 Popup，宽度 284dp，高度目标是锚点剩余空间与窗口 72% 较小者，内部滚动，底栏倍速/字幕菜单可限制到进度条上方；容器自身有 origin-aware scale + fade。代码：[PlayerFsMenus.kt:111-205](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerFsMenus.kt#L111-L205)。

发现：

- **最小高度钳制可能与可用空间矛盾**。高度计算在空间不足时仍 `coerceAtLeast(180.dp)`；而 popup 固定宽 284dp，定位仅限制左上角，不改变自身尺寸。极低高度（横屏小窗/分屏/桌面自由窗口）或小于 308dp 的宽窗口中，面板可盖控件/锚点或无法满足左右 margin。代码证据：[PlayerFsMenus.kt:123-141](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerFsMenus.kt#L123-L141)、[PlayerFsMenus.kt:178-205](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerFsMenus.kt#L178-L205)、[PlayerFsMenus.kt:220-235](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerFsMenus.kt#L220-L235)。**需短高度设备测**；建议从真实 `windowSize` 同时 clamp 宽高，并按上/下较大剩余空间决定展开方向。
- **Popup 获取键盘焦点后键盘命令归属不明**。全屏菜单 `focusable=true`，播放器快捷键由根 Box `onPreviewKeyEvent` 收。需用实体键盘验证弹层打开后 Esc 是否收弹层优先、Space/方向键是否仍发到播放页、关闭后焦点是否回到锚点。证据：[PlayerFsMenus.kt:178-187](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerFsMenus.kt#L178-L187)、[PlayerScreen.kt:1659-1739](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L1659-L1739)。不能静态下结论说键盘已坏。
- **倍速/字幕等 drill-in 页直接替换，没有子页动画**。容器动画只包 Popup 整体；`when(page)` 直接换内部页面。证据：[PlayerScreen.kt:2002-2023](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L2002-L2023)。应有单向短 fade-through / 8dp 来向移动，回退反向、选项确认后关闭沿原退场曲线。

### 4.2 弹层总体问题

- EpisodePanel / FileInfoCard 条件挂载后没有完整对称的淡入和淡出生命周期；`NpSheet` 与 FS menu 则有专门开关过渡，导致“有些菜单优雅，有些突然出现/消失”的产品内不一致。证据：[PlayerScreen.kt:2532-2559](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L2532-L2559)、[PlayerScreen.kt:3018-3080](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L3018-L3080)、[NpSheet.kt:217-265](../None Player/core/ui/src/main/kotlin/com/noneplayer/core/ui/NpSheet.kt#L217-L265)。设计目标应是**每一个进入/离开视图都有有意义的配对动画**，并支持中途打断，减少轻微 opacity + transform 即可，不需全屏飞入。
- FileInfoCard 外层 scrim 负责点击关闭，但卡片 Column 不消费点击；卡片内部点任意元信息也可能触发 scrim 关闭。当前没有复制路径的视觉入口。证据：[PlayerScreen.kt:3026-3041](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L3026-L3041)。
- 弹幕 pill 与控制栏一起淡出，显示区固定右上 `padding(top=64dp,end=16dp)`。若顶栏在状态栏/刘海/横向安全区变化下位置不同，弹幕 pill 是否重叠标题/锁定按钮需大/小屏实测；不能仅凭 64dp 说明通用安全。[DanmakuOverlay.kt:265-289](../None Player/plugins/plugin-danmaku/src/main/kotlin/com/noneplayer/plugins/danmaku/DanmakuOverlay.kt#L265-L289)。
- 播放控制栏当前正确将弹幕/字幕 overlay 限制在**视频画面内框**，不要将此实现误标成铺到全窗口；这是项目曾修复的问题，证据：[PlayerScreen.kt:4294-4308](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L4294-L4308)。

## 5. 浏览页、窗口关系与动画

### 5.1 确认/风险项

#### P2 · Medium 横向窗口 720–839dp 的“点左侧内容却不去详情/播放”路径不一致风险

库页只有 `windowInfo.isDesktopLike`（Expanded 宽度、横向且高非 Compact）时，点击媒体才进入 detailItem；否则直接进独占播放页。详情页自己以 `maxWidth >= 720dp && siblings.size > 1` 决定双栏。这两个入口阈值不一致：约 720–839dp 的 Medium 横向分屏满足详情双栏宽度，却不满足 `isDesktopLike`，因此点击列表项目跳到独占播放，而不会进入预期的左列表+右内容双栏详情。不是“点了条目却渲染到右侧”的同一缺陷，但属于窗口阈值契约不统一，值得先确认产品想要什么。

证据：[LibraryScreen.kt:248-265](../None Player/plugins/plugin-library/src/main/kotlin/com/noneplayer/plugins/library/LibraryScreen.kt#L248-L265)、[VideoDetailScreen.kt:135-140](../None Player/plugins/plugin-library/src/main/kotlin/com/noneplayer/plugins/library/VideoDetailScreen.kt#L135-L140)、[NpWindowInfo.kt:153-164](../None Player/kernel/kernel-ui-api/src/main/kotlin/com/noneplayer/kernel/ui/api/NpWindowInfo.kt#L153-L164)。**需设备/尺寸验证** 720、800、839、840dp 与低高度组合。修正建议：把“进入详情阈值”和“详情内部两栏阈值”定成共享窗口 policy，或明确 Medium 档不提供详情。

#### P2 · 文件夹网格与视频列表各自从 index 0 做 stagger，会同批进场

同一个 `staggerWindow` 下，子文件夹 `index=0,1,…` 和视频 `index=0,1,…` 分别开始错峰；两类条目共同可见时，首个文件夹与首个视频同时获得 index 0 时序，第二项也重复同时间窗，错峰看成“两组同时弹”。动画是否真的明显需截图/慢动作验证，但索引安排源码可确认。

证据：[LibraryScreen.kt:1484-1488](../None Player/plugins/plugin-library/src/main/kotlin/com/noneplayer/plugins/library/LibraryScreen.kt#L1484-L1488)、[LibraryScreen.kt:1544-1588](../None Player/plugins/plugin-library/src/main/kotlin/com/noneplayer/plugins/library/LibraryScreen.kt#L1544-L1588)、[Motion.kt:480-507](../None Player/core/ui/src/main/kotlin/com/noneplayer/core/ui/Motion.kt#L480-L507)。建议跨 item group 使用递增的统一 index，或让“文件夹组先入场、媒体组随后”的相位区别有意识且有设备截图证据。

#### P2 · 搜索结果头在窄窗口把五组控件挤进一行

结果头一行含标题、排序菜单、升降序、网格/列表切换、数量；标题 `.weight(1f)` 只吃剩余宽度，没有触发断行/横滚策略。窄分屏下标题可能缩到不可读、菜单标签挤压、操作热区互相太近。

证据：[SearchScreen.kt:453-505](../None Player/plugins/plugin-library/src/main/kotlin/com/noneplayer/plugins/library/SearchScreen.kt#L453-L505)。建议在 Compact 宽度让低频排序/数量下沉或折进更多菜单；以 280/320/360/400dp 实测按钮命中、标题最小可读宽度，不能只看平板。

#### P2 · 浏览视图“网格/列表”切换有底部 Sheet，但内容切换/布局重排的动效需逐项对照

库页交互控件先打开“视图”Sheet，再点网格/列表；Medium/Expanded 网格列由 Adaptive 自适应，Compact 固定列数。此设置 Sheet 有自己的开合动画，但网格与列表实际换布局仅依赖 LazyGrid item 列表重组，是否保留首屏位置、是否交叉淡化、换列时卡片是否突跳需要现场验。证据：[LibraryScreen.kt:1956-2015](../None Player/plugins/plugin-library/src/main/kotlin/com/noneplayer/plugins/library/LibraryScreen.kt#L1956-L2015)、[LibraryScreen.kt:1490-1499](../None Player/plugins/plugin-library/src/main/kotlin/com/noneplayer/plugins/library/LibraryScreen.kt#L1490-L1499)、[LibraryScreen.kt:1561-1588](../None Player/plugins/plugin-library/src/main/kotlin/com/noneplayer/plugins/library/LibraryScreen.kt#L1561-L1588)、[LibraryScreen.kt:1852-1858](../None Player/plugins/plugin-library/src/main/kotlin/com/noneplayer/plugins/library/LibraryScreen.kt#L1852-L1858)。此项**不是断言缺动画**：`animateItem` 可以处理 item 外观，仍需验证整个网格↔列表转换是否符合直觉，并在切换期间保持同一媒体可见位置。

#### P2 · 网格密度偏好被复用为 3 列密度，但 Adaptive 最小宽可能意外排出很多列

Medium/Expanded 的 `gridMinCell()` 在用户选“3列/紧凑”时返回 120dp；超宽平板视口上会自动得到远多于三列，而偏好标签与用户理解的列数不再相符。代码注释称“把偏好重新诠释为密度档”，但 UI 视图面板却仍向 Compact 用户呈现真实“列数”概念。[LibraryScreen.kt:1844-1858](../None Player/plugins/plugin-library/src/main/kotlin/com/noneplayer/plugins/library/LibraryScreen.kt#L1844-L1858)。这是**产品语义需确认**：若这项实际是密度，名称应为“大卡/小卡”；若是列数，非 Compact 应按指定 count 而不是 Adaptive min width。

#### P3 · 359/360dp 迷你栏动作布局可能出现阶跃压缩

E129 历史记录 `<360dp` 将部分动作折入“更多”，≥360dp 恢复耳机与下一集等入口；单 dp resize 可能骤减标题空间。该历史记录在当前工作区未找到，**不能当成本轮已复核事实**；请以当前实现 [MiniPlayerChrome.kt:202-289](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/MiniPlayerChrome.kt#L202-L289) 的断点为准，再测 320/359/360/400dp，观察标题宽度、按钮位置跳变和触控目标；若实现确有单点断崖，可考虑渐进收纳。

## 6. 手机、平板、横竖屏专门核查

### 当前已存在的产品策略

- 手机竖屏：视频上方/信息操作下方，页面不强制旋转；用户按全屏请求横屏，设备自然旋转横持也进入横向播放形态。
- 平板竖屏：按可用宽度显示视频及下方信息，不强制切屏。
- 横向全屏：视频铺满横向窗口，隐藏系统栏；弹幕/字幕被限制在视频画面区域。
- 类 PC：导航 Rail + 库列表 + 右侧常驻播放窗；返回/全屏与手机全屏语义有区别。
- 仅听音频横窗：黑胶左、内容右，设计规格与代码声明此形态不滚；低高度风险已在历史文档列待设备核验。

主要依据：[设计文档.md:617-642](设计文档.md#L617-L642)、[设计文档.md:644-656](设计文档.md#L644-L656)、[PlayerScreen.kt:1774-1778](../None Player/plugins/plugin-player-ui/src/main/kotlin/com/noneplayer/plugins/player/ui/PlayerScreen.kt#L1774-L1778)、[VideoDetailScreen.kt:135-190](../None Player/plugins/plugin-library/src/main/kotlin/com/noneplayer/plugins/library/VideoDetailScreen.kt#L135-L190)。

### 重点验证矩阵（避免“左边点、右边开”错看成随机问题）

| 场景 | 应该发生 | 需检查的第一直觉问题 |
|---|---|---|
| 手机竖持 → 点击视频 | 播放页竖屏；有清晰全屏入口 | 不应因媒体宽高比自动横屏；退出全屏应留播放页 |
| 手机点全屏 | 横屏沉浸；返回先退全屏，再次返回离页 | 旋转锁定拒绝时需可操作提示并能退出；系统返回不能循环吞键 |
| 手机物理横持（未点全屏） | 横向播放形态（按系统传感器） | 返回逻辑看的是“是否由用户点全屏”而非只看横向状态；验证外接旋转锁 |
| 平板竖持、横持 | 竖持仍可浏览；横向宽屏类 PC 三栏，条目选择先看详情/右栏 | 720–839dp 中档是否跳过预期详情；屏幕方向/WindowSizeClass 在分屏/横持改变时是否重算 |
| 右栏有播放 → 点库另一条 | 导航页面在左内容列；右栏仍播放既有媒体 | 是否被右栏抢点击/列表重建；检查滚动锚点和暂停态保持 |
| 小窗/自由窗口矮横屏 | 控件、倍速菜单、只听内容均能访问 | FS Dropdown 固定宽、最低高 180dp；AudioOnly横窗右栏滚动风险；尺寸阈值突变 |
| 折叠/半开态 | 当前已明确不承诺几何避让 | 折痕能否穿过文字/控件；如产品要支持，需新增铰链 bounds 方案，而非仅加动画 |

**对用户说的“左边点击后右边显示（平板问题）”的当前判读**：源码架构有意让宽屏点击列表进入详情/右栏或右栏常驻播放，播放 surface 放右侧不是异常；更可能需要追踪的是真实方向/宽度档位是否让相同点击走到“直接整页播放”而非右栏（上方 720–839dp 阈值不一致风险），以及当前被点媒体与右栏播放媒体是否一致。由于本轮未见运行现场、旧截图、复现步骤，这一条先记**重点设备复核而非已确认缺陷**。

## 8. 动画覆盖审查：哪些应有、哪些不要过度

### 已有动效，不建议重复实现

控制栏 280/220ms 淡移；FS 菜单 150ms 锚点缩放淡入/退场；NpSheet 跟手拖拽、速度关闭、scrim 联动；Tab 有胶囊/图标/内容方向过渡；音频模式淡切；媒体列表部分条目 animateItem/stagger；进度拖动 thumb/气泡反馈；播放器错误/结束态有入场 scale/fade。见第 2、4、5 节引用及：[NpSheet.kt:91-179](../None Player/core/ui/src/main/kotlin/com/noneplayer/core/ui/NpSheet.kt#L91-L179)、[KernelTabScaffold.kt:285-345](../None Player/kernel/kernel-ui-api/src/main/kotlin/com/noneplayer/kernel/ui/api/KernelTabScaffold.kt#L285-L345)。

### 动画缺失或需证实

| 交互 | 静态判断 | 优雅动效建议 |
|---|---|---|
| FS dropdown 内 MAIN → 倍速/字幕等子页 | 代码可确认当前只是分支替换，无内部 transition | 150–200ms fade-through + 8dp 来向滑动；返回逆向；面板整体位置保持 |
| FileInfoCard | 代码可确认无显入退场，外部点击即卸载；内部点击会冒泡关闭 | scrim alpha 与卡片 scale 0.97→1 / 退场反向，卡片内容阻断 click；支持 Back/Esc/关闭钮 |
| EpisodePanel | 代码可确认条件挂载，无同 NpSheet 一样出场/拖拽生命周期 | 底部轻移入+scrim 淡入；退出同源；支持下滑与返回，保留播放画面 |
| 类 PC 右栏出现/消失 | 壳层代码未见对宽度/进入做动画；要设备确认是否肉眼突跳 | `animateContentSize`/边界受控宽度 transition，右栏内容 fade；播放 Surface/会话不要销毁重建 |
| 网格 ↔ 列表、Adaptive 列数突变 | 部分 item animateItem，但切换整体位置/滚动锚点效果不确定 | 保持当前媒体 key 与首屏锚点；只做必要的交叉淡化/尺寸重排，不要让每张卡片独立大幅飞动 |
| 搜索新结果 | 输入已有 120ms debounce，但结果替换/空态切换的可感知过渡需确认 | query 版本对齐后做轻淡入；debounce 窗内旧结果需禁点/占位 |
| 亮度/音量 HUD 与手势 seek HUD | 已有淡入/淡出、显示时间；手感/位置需真人验证 | 保持数据 1:1；反馈从起手出现且结束后短淡出，避免慢呼吸/循环动画 |
| 屏幕旋转/窗口 resize/分屏 | 旋转是系统行为；各页面响应式重排是否连续未统一 | 不额外给每个像素尺寸 change 加弹簧；形态切换用短 opacity/layout morph，减少 Surface 重挂、尊重 Reduce Motion |

**动效判断标准**：动画服务于“从哪里来、到哪里去、状态有没有改变、哪个内容仍在播放”。优先 opacity/transform、统一 Motion tokens、可中断/Reduced Motion；不为所有元素加持续呼吸、弹跳或随机 motion。切换动画必须不让用户丢失焦点/当前媒体/滚动位置。

## 10. 建议复测矩阵（优先按用户第一直觉）

### 播放与菜单

1. 视频/音频、播放/暂停、单条/队列、0.5x/1x/2.5x 倍速；依次竖屏↔全屏↔右栏，检查速率值/菜单当前选中/状态 pill 是否始终一致。
2. 播放期间单击、双击各分区、横滑 seek、竖滑亮度/音量、按住 3x；设备 60/90/120Hz 下确认判断一致、指示器不压控制、seek 取消确实回滚。
3. 播放栏显隐：刚进、播放 3.5s 后、暂停、拖动进度、打开 FS 菜单、打开字幕/选集、锁定、接鼠标、拔鼠标；菜单锚点不可随控制栏消失，所有状态最终可退出。
4. 全屏菜单：顶栏 ⋯ 向下、底栏字幕/倍速向上、进度条附近、横屏 400dp 高/宽 320dp 窗口；记录锚点是否被遮、Menu 是否超出、关闭后焦点回到触发按钮。
5. 键盘：打开菜单后按 Esc/Space/方向；控件自动隐藏后按 Space/M/seek；验证返回顺序、焦点、控制栏唤回策略。
6. 弹幕来源：自动文件→内嵌轨→手动文件→清手动→另一内嵌轨→关闭；确认每次只显示预期来源、不双绘同一行、pill 名称与来源同步。

### 浏览/模式

7. 搜索 query：`.`, `.mkv`, `mkv`、快速改词后立即点结果；确认显示项、历史 query、打开媒体归同一关键词。
8. 跨来源重号：建立 source A/B 均有 `mediaId=1`，但不同 URI/媒体；分别播放几秒，检查库卡进度/最近排序不会串。
9. 详情入口宽度：719/720/839/840dp，分别横竖向、高 400/480/800dp，有无兄弟项；检查同一点击结果在手机、分屏、平板是否符合产品约定。
10. 网格列表切换：Compact 1/2/3 列，Medium/Expanded 舒适/紧凑密度，切换过程中首屏锚点、列数与历史操作是否稳定；观测 folder+video stagger 是否重复同拍。
11. 迷你栏 320/359/360/400dp 逐档缩放：动作折叠、标题宽度、目标尺寸、标签/菜单是否突然跳变。
12. Android 手机 320/360/412dp、平板 600/720/840/1280dp、旋转/自由窗口/折叠半开；检查系统栏、刘海/手势 inset、窗口缩小后的菜单/控件可达性。

### 动画与可访问性

13. 每种状态切换截 t≈0、过渡中点、t=1 三帧，检查无瞬闪/叠帧/硬切；重点 FileInfo、选集、FS 子页、Pane 占位、网格列表、搜索无结果。
14. 系统 Remove animations / Reduce Motion：位置/缩放归零或短淡入，仍能看懂状态、完成操作；确认焦点没有落入已经淡出但未卸载的层。
15. TalkBack：按钮动作名、当前倍速/字幕/弹幕状态、seek `setProgress`、弹层标题/焦点进入与关闭后恢复；无障碍用户不依赖颜色区分状态。

### 14.2 实测采出的新缺陷 E130-D9（已修，并已复验）

**现象**：**所有底部 Sheet 的面板整体下移一个状态栏高度，底边溢出屏幕 52dp**，导致底部内容被切：

- 字幕面板：四个偏移按钮（−50/−250/+250/+50ms）只剩顶部一条，**文字仅 7px 可见**（既看不清也点不准）；
- 「播放选项」面板：最后两行（`允许屏幕截图` / `持久生效 · 限播放页`）bounds 为 `[0,0][0,0]`，**整行不可见**。

**取证过程（逐层排除）**：
1. 先怀疑是面板太高被 `clip` 截断 → 实测 `panelH=1028px`、容器 `rootH=2856`，面板**确实贴到容器底**，位置本身没错；
2. 再怀疑内容溢出但 `verticalScroll` 不生效 → 加 `weight` / 显式 `heightIn` 上限 / 自定义 `popupPositionProvider` **三次改动实测 bounds 逐字节不变**；
3. 打点测真值定案：`view.getLocationOnScreen().y = 156`、`boxH = 2856`、而 **弹窗内 `WindowInsets.statusBars.getTop() = 0`**。
   → 弹窗窗口属性是 `(0,0)(1281×2856)`（铺满屏幕），但窗口内的 ComposeView 被平台按 `fitSystemWindows` **下移了一个状态栏高度**（156px = 52dp），自身高度却仍是整窗高 2856 —— 内容底边因此落在屏幕 3012，**溢出 156px**；面板 `BottomCenter` 对齐，底边正好被切掉这 156px。
   → 也解释了第 2 步三次改动为何全部无效：拿 `statusBars` 做补偿量在弹窗内恒为 **0**，等于没补。

**修法**（`core/ui/NpSheet.kt`）：用**视图自身的屏幕 Y** 作补偿量，在面板已有的 `graphicsLayer.translationY` 上减去它。走绘制层平移、不改布局坐标，因此不影响测量、滚动位置与已有的下滑关闭逻辑。同时给内层滚动体补一个**具体高度上限**（`heightIn(max = sheetMaxHeight - 把手块)`），让 `verticalScroll` 在内容真的超高时能滚动——此前只靠外层 `heightIn(max=)` 时，滚动体量到的是无界高度，会"以为放得下"而不滚动。

**复验（同一台模拟器）**：

| 判据 | 修复前 | 修复后 |
|---|---|---|
| `允许屏幕截图` bounds | `[0,0][0,0]`（不可见） | `[156,2808][408,2856]` ✅ |
| 偏移按钮文字 bounds | `[147,2849][247,2856]`（7px，被切） | `[147,2693][247,2732]`（39px，完整）✅ |

### 16.2 新采出的真缺陷 E132：**弹层打开时播放器全部快捷键失效**（未修复，已记账）

**现象**：任意底部 Sheet 打开时，播放页的键盘快捷键**全部无效**——空格（播放/暂停）、
方向键（seek/音量）、`M`、`F`、`L`，以及 **`Esc`**。实测：打开「画面」面板后按 `L`，
面板不动、锁定也不触发；打开「字幕设置」后按 `Esc`，面板不关。

**根因**：`NpSheet` 的宿主是 `PopupProperties(focusable = true)`（这是 E100 为了实现
无障碍可达定下的，不能去掉），它作为独立窗口**自己吞掉按键**，播放页根节点那层
`onPreviewKeyEvent` 根本收不到事件。

**为什么这条比"不方便"更严重**：设计文档 §5.5 明确写着返回链是
「弹层关闭 → 退全屏 → 路由返回」且**「`Esc` 等同返回键」**。系统返回键能关弹层
（走 `onDismissRequest`），`Esc` 不能 —— **这是规格内的功能缺口**，不只是手感问题。

**本轮试过的修法（已回退，不留在代码里）**：给弹层内容挂
`onPreviewKeyEvent { Esc -> close() }`；第一次无效，补 `.focusable()` 让容器成为焦点目标后
**仍然无效** —— 说明该弹窗的按键压根没有进入 Compose 的焦点派发链（不是"焦点在别处"，
是"事件没进来"）。既然验证不出效果，就不留这个改动（它还会给 Sheet 增加一个焦点目标、
扰动内部焦点顺序，属于纯噪音），已 `git checkout` 回退。

**下一步方向（建议，未实施）**：本项目已有一个现成的同类机制可复用 —— E99 为
"三栏浏览态键盘全哑"做的**窗口层兜底派发**（`SessionKeyProvider`，见《审查文档.md》§2 E99）。
把弹层打开这一态也纳入那条兜底链（或在 `Popup` 层面统一拦第一手按键），比在每个弹层里
各挂一份键处理更符合本仓"一处判定、全局消费"的既有姿势。这属于**契约层改动**，
且需要真键盘走查，故本轮不做、留待裁定。
