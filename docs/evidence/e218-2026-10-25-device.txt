1. 本批改动（缺陷修复，两处）
----------------------------------------------------------------
【缺陷】外部深链 `noneplayer://player?uri=…&fs=1` 冷启在自然竖屏设备上不进
全屏（落竖屏播放页）。根因两层，均在真机 logcat/旋转观测实锤：

① **fs 子集深链模板缺失**（路由层）：`PlayerScreenProvider.deepLinks` 没有
  能匹配 `?uri=…&fs=1` 形状的模板——A1-2 的「模板逐项比对」下它落到
  `?uri={uri}` 那条上，`fs` 被静默丢掉。instrumented release 实锤：
  `FsDebug: effect entry=false`（fs 根本没进路由）。
  修复：补三条 fs 子集模板（`uri&title&mime&id&fs` / `uri&id&fs` / `uri&fs`），
  `PlayerDeepLinkTemplateTest` emitted 清单同步补形状（缺模板测试先红）。

② **冷启确认窗过短**（PlayerScreen）：`setFullscreen(true)` 发出
  `requestedOrientation(LANDSCAPE)` 后，`awaitLandscapeApplied` 只等 1200ms；
  冷启时请求发出在首帧之前，转屏落地超出窗口 → 误判失败 → 回退
  FollowSensor 把请求撤销。修复：`setFullscreen` 增加 `confirmMs` 参数，
  深链冷启路径给 4s 长档（`ORIENTATION_CONFIRM_COLD_START_MS`）；热态
  点按维持 1.2s；真拒绝（信箱化）场景只是 toast 晚一点。

复验（真机同一台）：冷启深链 `entry=true` + 显示 `ROTATION_90` +
全屏沉浸 UI（系统栏隐藏、自绘时钟补位；竖版视频信箱化居中属正确渲染）。
`requestedOrientation` 观测：修复前全程 UNSPECIFIED，修复后按预期持有
LANDSCAPE 直到用户退出。

**测试方法教训**：`adb shell am start -d "...&fs=1"` 的 `&` 会被设备端 shell
当后台分隔符——`fs=1` 根本没进 intent（`?fs=1&uri=…` 形状则整条命令被拆、
应用收到空意图）。必须写成
`adb shell 'am start -a android.intent.action.VIEW -d "noneplayer://player?…&fs=1"'`。
此前平板批次（E214 等）的 fs 深链「能用」是因为平板自然横屏本来就不需要转屏，
该路径从未被真正覆盖过。
