E225 轨道号文件内稳定序号 真机证据（JVM 单测 + 模拟器冒烟，2026-10-25）
================================================================

本批修一个**渲染正确性真缺陷**：弹幕飞行途中集体换道（y 瞬移）。
装机：`adb install -r app/build/outputs/apk/release/app-release.apk`
（E225 构建，模拟器）。

----------------------------------------------------------------
1. 缺陷与修复
----------------------------------------------------------------
【缺陷】`DanmakuPlanner.plan` 的车道号 = **窗口内到达序号** mod 轨道数：
窗口每滑一帧（前面任何一条弹幕出屏/被密度上限裁掉），后面所有弹幕的窗口内
序号整体前移 → 车道号全部变化 → **在飞的弹幕集体瞬移到别的轨道**（y 跳变）。
密度上限 `takeLast` 的前段裁剪会再叠加一次移位。弹幕越稀疏越显眼。

【修复】车道号改用**文件内稳定序号**（按模式分别计数，与文件同寿）：
- `Danmaku.kt` 新增 `stableLaneOrdinals(danmaku)`：与弹幕列表平行的序号表
  （滚动/顶/底各自独立计数，O(N) 每次**文件加载只算一次**，remember 缓存）；
- `plan` 增加可选 `laneOrdinals` 参数：窗口元素携带全表下标，车道号取
  `ordinals[全表下标] mod 轨道数`；缺省 null 回退旧窗口计数（内嵌 spawned
  无稳定文件序，行为与旧版一致）；
- 「占用时长」语义随稳定序号成立：同车道相邻两条序号差 ≥ 轨道数才可能
  同屏相接，单条对车道的占用横跨其整个存活期。
- Overlay：文件源 `remember(items) { stableLaneOrdinals(items) }` 传入；
  内嵌源传 null。

【测试钉住】`DanmakuPlannerTest` 增 3 项：
- `stable ordinals count per mode`：五条混编弹幕的序号表（滚动 0,1,2 /
  顶 0 / 底 0——各模式独立计数）；
- `lane stays stable as the window slides`：**同一条弹幕在窗口滑动前后
  （前一条出窗）车道一致**——旧实现此断言必红；
- `fallback without ordinals keeps window-counter behavior`：内嵌路径
  行为与 E225 前一致（回归钉）。

3. 真机（模拟器）冒烟
----------------------------------------------------------------
- E225 构建装机后弹幕渲染无回归（滚动弹幕出生右缘/左移/出屏路径同前，
  E225 前的既有 planner 用例 27 项全过）；
- 「换道瞬移」的可见对照需要密集弹幕片源（同屏多条 + 前后出窗交错），
  模拟器夹具为单条/少量——缺陷机理与修复由 JVM 断言钉住
  （`lane stays stable` 在旧实现必红），真机对照录屏记为边界。

----------------------------------------------------------------
4. 边界
----------------------------------------------------------------
- 稳定序号按**文件内时间序**计数：同 timeMs 的先后由文件行序决定
  （stable，但与播放端无关）；
- 内嵌 spawned 无文件序，维持窗口计数（每次倒退重建已清表，行为回退可
  接受）；若未来要内嵌也稳定，需要给 spawn 记录持久序号，另立任务。
- 车道分配仍是确定性取模，不做状态式占道（设计文档 §批次 6 的既有取舍
  不变）。
