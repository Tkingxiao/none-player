A. 删除失败 → 应用风格权限引导卡（替代系统二次确认）
  1) 长按卡片 → 「删除」→ 应用确认卡 → 确认；
  2) 直连三步（老树升级 READ|WRITE → 树下钻删文档 → ContentResolver.delete）均无权限：
     既有**只读**持久化授权无法原地升级（升级调用静默失败，`dumpsys activity permissions`
     复核 mode 仍 0x1），树上 deleteDocument 与直删都被系统拒绝；
  3) 不再弹 MediaStore 系统确认框，而是应用自己的卡：标题「删除失败」+ 说明
     "删除设备文件需要「所有文件访问」权限，或该文件所在目录的写入授权…" + 取消/去开启
     （截图 01-delete-failure-card.png；ui-failure.xml 节点：删除失败 / 去开启）。

B. 「去开启」→ 系统设置 → 重试删除成功
  1) 点「去开启」→ `topResumedActivity=Settings$AppManageExternalStorageActivity`
     （本应用的「所有文件访问权限」页，截图 02-settings-page.png）；
  2) 打开开关 → `appops get` 出现 `Uid mode: MANAGE_EXTERNAL_STORAGE: allow`；
  3) 返回应用重试 → toast「已删除」（截图 03-delete-success.png）、
     /sdcard/Movies/E232/saf-delete-test.mp4 消失、E232 目录为空、媒体库 96 视频。

C. 代码侧口径（本批）
  - 三处目录选择器（库页 / 库页 Sheet 释放 / 扫描器设置）改为持久化 READ|WRITE，
    释放同步按 READ|WRITE——**新授权**的目录在 SAF 树里可直接删文档，无需 all-files；
  - 删除前对既有目录做一次尽力升级（多无副作用）；
  - 失败出口唯一：应用风格引导卡 + 去开启（API30+ 直达本应用 all-files 页，
    打不开退总表；API26–29 退应用详情页）。

稳定性：与 A/B 流程同期 `adb logcat -d` 检索 0 条 FATAL EXCEPTION。
边界：
  - **既有只读授权无法原地升级**（实测升级静默失败）——存量用户要么开「所有文件访问」，
    要么移除并重新添加扫描目录（新授权含写位）；
  - 「新授权 READ|WRITE → 无需 all-files 直接删」未在设备复测（未走 SAF 选择器重授流程），
    以系统 API 语义与单测口径为准；
  - API 26–29 设备没有 all-files 概念，引导落应用详情页；该档直删还依赖写外部存储权限，
    未在旧 API 设备实测（本机 API 33+）。
