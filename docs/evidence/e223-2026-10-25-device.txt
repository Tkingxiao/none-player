E223 弹幕文件读取有界 + 内嵌 spawned 倒退重建 真机证据（emulator Pixel_Tablet，2026-10-25）
================================================================

本批为 DanmakuOverlay 文件加载/内嵌通路的加固，验证以 JVM 单测为主 +
模拟器冒烟（弹幕文件加载路径无回归）。装机：`adb install -r
app/build/outputs/apk/release/app-release.apk`（E223 构建）。

----------------------------------------------------------------
1. 改动
----------------------------------------------------------------
- **文件读取有界**：`loadFileSource` 的 `stream.readBytes()` 全量读改为
  `readBoundedBytes`（上限 16MB，多读 1 字节判超限——不把误标成弹幕扩展名
  的大文件整段读进内存再解析，OOM 面收口）。超限跳过该候选并留 logcat
  提示（「弹幕文件超过 16MB 上限，跳过」）。编码判定（UTF-8/GBK fallback）
  留在调用方 decodeText，有界读只管字节数。
- **内嵌 spawned 倒退 seek 重建**：内嵌通路「新 cue → 立即 spawn」此前在
  倒退 seek 后会把旧 spawned（显示位置已失效）留在屏上，且 cue 重新出现
  造成重复 spawn。现按 `nextSpawnedOnCue` 重建：倒退（`isBackwardSeek`，
  新 position 比上次小 >1.5s）→ 清掉失效 spawn、保留当前位置正确的当前
  cue；列表维持**时间升序**不变量（乱序插入被排回升序，兜底）。
- 幂等口径：同 cue 文本不重复 spawn（既有 lastText 去重保留）。

----------------------------------------------------------------
2. 测试与门禁
----------------------------------------------------------------
- 新增 `DanmakuBoundedReadTest` 7 项：有界读 ≤上限全量返回 / >上限判
  Oversize / 恰好等于上限是 Content（且钉住 16MB 常量口径）/ spawn 追加
  保升序 / 倒退清旧留当前 / 乱序重排回升序 / 倒退判定阈值（1.5s，抖动与
  首帧不算）。
- 门禁（最终源码全跑）：test **151 套件 / 1050 项 / 0 失败**（基线
  150/1043 + 7 项）、lint 15 份 0 issue、release 29,208,295 B、
  debug 66,222,573 B（桶内吸收）。

----------------------------------------------------------------
3. 真机（模拟器）冒烟
----------------------------------------------------------------
- E223 构建装机后弹幕文件加载通路无回归（同目录匹配 → 有界读 → 解析 →
  渲染，np-e220 夹具 PLAYING）；
- 超限跳过的 logcat 提示需要 >16MB 的弹幕扩展名文件——以单测口径覆盖
  （Oversize 判定 + 停读），真机未造 16MB 假弹幕文件，记为边界；
- 倒退 seek 重建的真机可见行为（倒退后无残留弹幕、无重复 spawn）需要
  内嵌弹幕轨片源（ASS 内嵌 .mkv），素材欠账（§9.6 素材条目已有），以
  纯函数测试钉住重建语义。

----------------------------------------------------------------
4. 边界
----------------------------------------------------------------
- 16MB 上限是拍板值（正常弹幕文件 KB–MB 量级）；如需「超限截断解析前半」
  的更软策略另立任务。
- 倒退判定阈值 1.5s 拍板值（拖动回跳必然超过；同位刷新与毫秒级抖动不算）。
