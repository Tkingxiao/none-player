1. PS（mpeg2video + mp2）时钟冻结修复：三层根因均已闭环
----------------------------------------------------------------
修复前（E207 证据 §9）：PLAYING 后 position 冻结 529ms，10s 后
"Unexpected runtime error"；`NpFfmpegAudio create` 零日志。

修复后（22:39 会话，content id 1000015396）：
10-24 22:39:13.155 D/NpFfmpegDecoder(26257): audio decode pkt=0 in=417 out=2304 codec=mp2 (parsed)
10-24 22:39:13.xxx ... 状态：PLAYING，position=3526，buffered=10517
12s 后再取：state=PLAYING，position=44，buffered=10040，active item id 从 8 变 9
——10.5s 的 PS 正片正常播完并自动连播到下一条；0 ERROR / 0 "Unexpected runtime error"。

根因与修复（详见完成文档 E208）：
① NextLib FfmpegAudioRenderer 先把 AUDIO_MPEG_L1/L2 映射到 mp3 解码器并抢在
   自定义渲染器之前认领；NpFfmpegAudioRenderer 现插到 NextLib 之前（平台仍最前）。
② build-ffmpeg.sh 把 parser 写成不存在的 mp3（configure 静默忽略）；MP2 的
   PES 载荷不按帧对齐，第二个包起 avcodec_send_packet 恒 INVALIDDATA。
   改 --enable-parser=mpegaudio，四 ABI 重编；prebuilt 里均可见
   mpegaudio_parser.o（llvm-ar t 核对，4/4）。
③ 音频 JNI 输入直接指向 direct buffer，没有 AV_INPUT_BUFFER_PADDING_SIZE；
   解码前复制进 av_new_packet（自带 padding），MP2/WMA 共用。
另外，mp2 属于本批新增白名单，平台无 L2 解码器；parser=on 是运行时证据：
10-24 22:13:12.184 D/NpFfmpegDecoder(18406): audio create codec=mp2 parser=on

测试内断言：seek(0, 30s) 后首个视频样本 flags 含 KEY_FRAME，pts ∈ [30s,32s)；
首个音频样本 pts ≥ 30s。
日志证据（22:25:58 会话）：
  seek fallback: target=30000000 restart dataPos=0 waitKey=1
  seek keyframe reached: pkt=30300000us

修复的四个 seek 缺陷（E208）：
① iformat->name 实际是 "mpeg"（av_find_input_format("mpegps") 只是别名），
   旧 strcmp("mpegps") 从未命中，PS 一直走通用 avformat_seek_file，而非
   "回起点+丢包"；
② 关键帧等待把 npff_type_of 的 1 与 AVMEDIA_TYPE_VIDEO(=0) 比较，从未生效；
③ 首个 ≥target 的包就把 seek_target 清掉；夹具里视频到 30.02s 时音频仍
   29.60s，迟到音频从目标前 0.4s 开始播。目标保留到下次 seek，只丢迟到包；
④ avformat_flush 后没有 avio_seek(0)，AVIO 旧缓冲会把旧位置数据重复吐出；
   缓冲区内部寻位时 pending=-1，重开位置改用缓冲区末端（npff_data_pos）。
另：SeekMap 时长为未知（RM/NUT）时不再把目标夹到 0（旧 coerceIn(0,0)）。

4. E206 回归：LegacyVideoRenderer 未加载 libnplegacy 就认领 WMV2
----------------------------------------------------------------
修复前（22:46:55，WMV1+WMA 播完自动连播到 wl-wmv2-regression.avi）：
  E/.noneplayer.app(27923): No implementation found for long
    com.noneplayer.core.media.legacy.LegacyNative.nativeCreate(...)
  E/AndroidRuntime(27923): FATAL EXCEPTION: ExoPlayer:Playback
  java.lang.UnsatisfiedLinkError: ... is the library loaded, e.g. System.loadLibrary?
根因：E206 参数化 LegacyVideoRenderer 后，默认 supportsFormat 只用
LegacyDecoderLibrary.codecName()（纯字符串映射），不再经过带 System.loadLibrary
的 supports()/isAvailable()；冷进程先认领 WMV2，createDecoder 直接调 nativeCreate。
修复：默认 codecNameFor 恢复 isAvailable() 闸；LegacyCodec 构造前同闸防御。

修复后（22:51 会话，同一路径）：
11s 后自动连播到 wl-wmv2-regression.avi（session metadata description 确认），
  D/NpPerf(29321): LegacyVideoRenderer surface clone ok src=86788410 clone=161654183
session PLAYING item 17 position=2034；0 FATAL / 0 UnsatisfiedLinkError。
