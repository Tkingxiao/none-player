## 4. 高优先级：正确性、数据与失败边界

### REV-01　不完整扫描仍可删除历史/收藏　P1 · 源码确认

- **依据**：`plugins/plugin-scanner-local/.../LocalMediaSource.kt:308–318` 仅靠目录解析/撤权生成的 `notes` 决定清孤儿；`queryHiddenDocuments:1020–1107` 预算耗尽或子查询失败只返回部分结果；`sniffUnknownFiles:1233–1308` 可因权限收缩返回空。`core/database/.../HistoryRepository.kt:214–220` 随后实际删除历史及收藏。
- **触发/后果**：已有收藏的隐藏文件在预算外、Provider 暂时失败，或曾可见的未知类型文件因权限收缩不再返回；这些暂不可见记录会被当成已删除。顶层查询抛出并被 `scan()` 捕获时不会进入该清理，不能把所有查询失败混称同一路径。
- **实现路径**：各扫描分支返回 `items + completeness + coveredScopes + warnings`；完整性沿聚合传递。只有当前 generation 且完整覆盖的范围允许 prune；部分结果保留未覆盖范围旧记录。缩略图删除、快照替换也服从同一门禁，不只保护 Room。
- **验收**：假 Provider 注入子查询异常/null、遍历超预算、权限收缩、空但完整扫描；前三类不删历史/收藏/旧快照，最后一类才允许确认删除；取消异常仍原样传播。承接历史 A15（两位号）与任务 A25/A33。

### REV-02　扫描目录前缀和卷边界不严　P1 · 源码确认

- **依据**：`LocalMediaSource.scopeSelection:727–779` 用 `relativePath + "%"`，Primary 分支不限定卷；`videoCollection/audioCollection` 查询 external 集合。`scanScopeFromTree → parseScanScope:1450–1457` 去掉路径首尾 `/`。
- **触发/后果**：选择 `Movies` 却也命中 `MoviesBackup/`；主存储根/子目录可能收进其他卷同路径的媒体。这是**应用选择范围失效**，不是绕过 Android 系统权限。
- **实现路径**：抽 `ScopeQuerySpec`，Q+ 同时限定卷与规范化目录子树，按目录分隔符构造前缀；Primary 根也限定主卷。保留 `%/_/\` 转义，低版本按完整存储根路径构造谓词。
- **验收**：主卷/第二卷 × `Movies/`、`Movies/sub/`、`MoviesBackup/`、含通配符目录的表驱动测试；SQL 参数真实执行后仅命中所选子树。不能只测 docId 解析。

### REV-03　移除目录没有作废在途扫描　P1 · 源码确认，时序待复现

- **依据**：`LocalMediaSource.scan:166–198` 的 CAS 只隔离 scan；`removeScanFolder:592–613` 不共享提交版本；`scanInternal:304/331` 直接发布列表、写快照。
- **触发/后果**：扫描已取到旧目录列表，移除最后一个目录后它才完成；旧结果可重新发布，使被移除目录“回来”。UI 禁用按钮不能作为并发正确性的唯一保障。
- **实现路径**：目录集变化递增 generation；扫描开始捕获；发布、清理、快照提交在同一串行提交段复核 generation。无效结果丢弃或重扫，目录移除作废旧任务。
- **验收**：用可控 barrier 暂停发布前扫描，再移除目录并恢复；列表保持空、快照不重建、历史不被旧扫描清理。覆盖 add/remove/观察者补扫交错。

### REV-04　新条目身份可能配上旧进度落盘　P1 · 源码确认，时序待复现

- **依据**：`PlaybackSession.open:574–582` 先替换队列/下标；`persistPosition:673–682` 直接读取引擎位置/时长，无身份校验；`ExoVideoPlayer.pollPosition:419–436` 在探测期间仍可读旧控制器媒体。
- **触发/后果**：A 播过十秒，打开 B 的探测尚未结束时关闭会话或显式落盘；A 的时间可能写入 B 的历史键。只补 `state != Buffering` 会误伤同媒体缓冲时的正常保存。
- **实现路径**：定义带 `sourceId/mediaId/clip/generation/applied` 的进度快照；写入只接受与目标匹配且已应用的快照，切换前保存旧快照。CUE 分轨共享 URI，不能只比 URI。
- **验收**：慢探测 A→B→stop、A→B→C、同 URI 不同裁剪轨；断言 B/C 不获得 A 的位置，A 的最后有效断点保留。DAO 写入失败另按 REV-06 收口。

### REV-05　4KB 头限制不等于分配有界　P1 · 源码确认

- **依据**：`FormatProbe.ProbeOutput.sampleData:419–441` 先 `ByteArray(length)`；`Mp4vAspRewritingExtractor.RewritingVideoTrack:105–141` 先按整段分配/写 hold，再判断 `HEAD_CAP`。
- **后果**：较大首样本或异常 length 可带来大数组和重复拷贝；读轮数预算约束不了单次分配。不是本轮已复现 OOM。
- **实现路径**：固定大小 scratch；探测只截头、剩余分块丢弃；改写器先读足决策头、发布格式并 flush 头，余下直接转发，保持字节顺序和 sampleMetadata 的 size/offset。**只把数组缩到 min(length, cap) 却继续读 length 是错误修法。**
- **验收**：假 DataReader 大 length/短输入/提前 EOF/分段到达；输入消费和下游字节完全一致，缓冲容量有界；保留 Simple 走平台、ASP/QPel 走专用链的回归。承接 A20 首样本项。

### REV-06　持久化 IO 失败没有完整降级路径　P1 · 源码确认，故障注入待做

- **依据**：`HistoryRepository.recent/favoriteKeysFlow:60–78` 在 `stateIn` 前无恢复；`PlaybackSession:582/680–682` 裸 launch 写库；`PlaybackService.onCreate:125–130` 首读仅超时兜底，没有 IO 异常回默认值。
- **后果**：磁盘满、数据库打不开、DataStore 读失败时可能出现未处理异常、共享流停止或服务启动失败。`prime()` 的单次捕获与 `SupervisorJob` 不构成每次读写的恢复策略。
- **实现路径**：仓库边界区分取消、可重试 IO 与结构错误；返回可观察的保存失败状态，保留最后可信数据并支持重试。`stateIn` 的上游用有界重试/恢复；服务首读失败回默认偏好。全局异常 handler 仅兜底记录，不能代替局部恢复，更不能转为空表后触发 prune。
- **验收**：可注入 DAO/DataStore 的读写失败、恢复后重订阅、取消；UI 不谎报保存成功，播放不因一次断点失败退出。迁移测试禁止 destructive fallback。承接 A23 异常兜底。

### REV-07　私有播放命令对外部控制器无差别开放　P2 · 源码确认，外部调用待测

- **依据**：exo 插件 Manifest 的 PlaybackService 已导出；`ScrubAwareCallback.onConnect:365–379` 为每个控制器添加 `np.scrub/np.crop/np.autoplay`；`onCustomCommand:382–410` 无调用身份复核。
- **后果/边界**：第三方可连接时，应用私有策略控制面也被授予；未做跨应用攻击复现，不表述为任意代码执行或文件泄漏。
- **实现路径**：私有命令仅授予同 UID 控制器，执行侧复核身份与参数；外部系统控制器保留必要标准媒体命令。**不要直接关掉 service 的 exported 来“修复”系统接入。**
- **验收**：同 UID 命令正常，独立测试包未获私有命令/调用被拒；通知、耳机与 PiP 标准控制不回归。

### REV-08　兼容档可能连唯一可用的平台软解也过滤掉　P1 · 条件风险

- **依据**：`NpRenderersFactory.HardwareOnlyVideoCodecSelector:104–118` 只返回硬件 codec；`PlatformDecoderSupport.hasPlatformDecoder:24–33` 的可播性判断却包含平台软件 codec，且不携带当前偏好。
- **触发/后果**：API 29+ 上只有平台软件 decoder，NextLib/MJPEG/legacy 对该 mime/profile 没有认领时，探测可播但兼容档播放端无候选。不能把“恒 ON”当成跨所有格式正确的证明。
- **实现路径**：按同一能力快照决定排序：有可用硬解则硬解优先；扩展确定可解才替代平台软解，否则保留平台软解保底。profile/secure/tunneling 约束不能丢，查询失败保留 Unknown，不直接改成确定“不支持”。
- **验收**：硬解存在、仅平台软解、仅扩展、全部不支持、查询异常五组；两档均覆盖 Simple/ASP、H.264 与异常能力信息；设备侧记录实际 decoder 名称，不只看开关。承接 A10/A17/A18。
