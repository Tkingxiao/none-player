## 1. 界面、手势与动效

1. **组合键与硬键盘语义**：Shift+→ 快进/快退、Ctrl+O 打开已实现并有语义单测；人工键盘走查仍缺。**注不进的原因说清**：`input keyevent` 没有 meta 参数（Shift/Ctrl 注不进去），`input -source keyboard` 只能给单键；出路是接实体键盘走一遍，或在仪器测试里直接构造带 meta 的 `KeyEvent`。
2. **指针热插拔**：缺陷已修，两个子句均有正反单测。**口径订正**：「不暴露 SOURCE_MOUSE」是**模拟器**的限制，骁龙真机上 `input mouse tap <x> <y>` **能注入出 SOURCE_MOUSE 的事件**（`input` 的 source 是位置参数，写成 `input mouse …`，不是 `-source`）。但热插拔判据要的是**设备接入/断开那一下**：`input mouse motionevent HOVER_ENTER` 这台直接抛异常、`MOVE` 也不产生可观察的悬停态，`dumpsys input` 里也没多出鼠标类设备。**出路**：接一只实体鼠标走一遍（悬停高亮随接入出现、拔出消失），或改用 `--eu`/uhid 造设备（要 root）。
3. **竖滑手感**：实现完成。**原判据前提作废**——「`input swipe` 注不进手势层」不成立：E144 四边死区起手不接管、E147 慢滑连续累加（亮度 0.50→0.65、音量 35→57）、E181 抬手 HUD 0.7s 即收与全屏竖滑 `mBrightness` 0.0740→0.2553，全是指注入采到的。只有**进度条那条轨**例外：`input swipe` 会被舞台横滑吃掉（Δx 416px→+32s、Δx 1166px→+82s 成比例），判它必须用 `input motionevent DOWN/MOVE/UP`。剩下的是**主观手感**（跟不跟手、力道），机器替代不了，只能人工。
4. **整屏 morph 动效**：几何/行为单测 47 项通过；真机逐帧已采到——`screenrecord --bit-rate 24000000` 出片平均 **41.5fps**，560ms 动画摊到 ~23 帧。**手法记牢**：`settings put global animator_duration_scale` **拉不动 morph**，`npDuration()` 只走 `npQuality().scaled()`（轻量档往下夹、从不放大），想靠放慢系统动画来采样是错的；`screencap` 连拍节奏实测 1586ms/帧，比整段动画还长，也采不到。判据五条全部对上：**无空黑帧**（起飞到落位每帧都有画面）、**画面是同一个 `TextureView` 在放大**（没有第二路解码）、**文字与按钮不糊**、**部件不自转**（⛶ 交接 `turnDegrees=0`）、**「只有一层页面」按用户裁定定稿为可接受**——起飞那一帧旧页面（媒体库 + 右栏播放器）按路由淡出、留在原位，右栏那格视频以淡影与飞行的新画面并存约 100ms（`morph-3-flight-oldrect-crop.png`），这层淡出**不算**判据要禁的「一大一小两层视频」，不改实现。**还缺一格：转屏那一轮**（`turnDegrees≠0`，部件按 `ROTATION_SHARE=0.4` 转角自转）仍无逐帧证据，**两台设备、三条路子全部试过**，记死免得下一轮重跑：① 平板 HyperOS 写 `user_rotation`——六次只吃两次，且要先 `accelerometer_rotation` 1→0 重新断言锁，`screenrecord` 占着 shell 时全灭；② 虚拟设备 `Pixel_10_Pro`（API 37）写 `user_rotation`——**完全不吃**（`accelerometer_rotation=0` 也照样不动，连桌面都不转）；③ 虚拟设备控制台注加速度（`auth` 后 `sensor set acceleration 0:-9.81:0` 回 `OK`、`sensor status` 显示 acceleration enabled）——**屏仍不转**。**出路**：要么手上有能物理转屏的真机/带窗口模拟器手动转，要么在手机形态用「竖屏播放页 → 转横屏自动进全屏」这条应用自己的路径补一轮（本轮未跑）。证据 `screenshots/B20/23043RP34C/`。
5. **降档帧收益 / shimmer 收益**：实现完成；**降档已上真机**——同手势 gfxinfo 帧数 A/B（带同长度空载基线对照）：Tab 切换平衡档 36–41 帧/次 ↔ 轻量档 10–12 帧/次，恢复平衡后 38–41 帧复现，约 **3.7×**。缺：shimmer 与其余令牌（Hover/Panel/Switch）的逐档真机对比；绝对时长这台机拿不到（`framestats` 不吐帧数组、`SurfaceFlinger --latency` 环形缓冲定标不到动画起点）。

   仍欠：1080p HEVC CQ/VBR 回退、转码吞吐/温升/画质（这三项不是合成能凑的，要真实素材与控温环境）。**顺带新记一条设备侧告警**：起播时 logcat 有 `MediaSessionImpl: UnsupportedOperationException: Make sure to implement MediaSession.Callback.onPlaybackResumption()`（pid 就是本应用）——挂了 media button receiver / MediaLibraryService 契约却没实现 `onPlaybackResumption()`，不影响播放，但「最近媒体」恢复面在系统里是缺的。
3. **FFmpeg 渲染器 Surface 克隆**：单测 3 项两机通过；端到端 `renderToSurface` 仍未走克隆。**本轮把「缺平台无解码器夹具」这条往前推了一步并排掉一个错解**：合成 `np-mpeg1.mpg`（MPEG-1，Android 无平台解码器）推上真机，结果**根本走不到渲染器**——`begin probe → probe done (i31) +287ms` 之后会话恒 `NONE(0)`，卡在**抽取器/探测**这一层（MPEG-1 Program Stream 本就没有平台 extractor），所以它证不了也测不了 `renderToSurface` 的克隆路径。**正确的夹具形态**应是「容器与 extractor 平台能过、只有 codec 平台解不了」，候选：MKV/AVI 封 **VC-1 / Theora / VP6 / MPEG-4 Part 2 ASP**（本仓库 FFmpeg 侧可解），而不是换容器不换 codec。仍缺这样一个夹具，本条继续挂着。
4. **换挂黑屏修复**：根因已定位并修复；缺独立复验。
5. **WMV2 花屏 / 切集后平台流起不来**：根因已修，模拟器证据；缺真机。
6. **音频模式（仅听/直通）**：仅模拟器验证；真机未验。
7. **androidTest 执行面**：6 个素材 blocked（无授权/干净检出为空），执行面未跑。
8. **WMV2/WMA 音频映射**：`wmvAudioMimeForTag`（PCM/MPEG/WMA tag）、PCM 编码、blockAlign、不可解提示已补并有 5 项单测；WMA extradata、浮点 PCM、声道位深、音画同步未验。
