## 7. 验证手法备注（合并旧档手法坑中仍常用者）

1. **环境**：Pixel_Tablet（2560×1600，density 320，自然横向，Android 15）为主验证机；adb 在 `%LOCALAPPDATA%\Android\Sdk\platform-tools`；`screencap` 读图坐标 ≠ 设备坐标（Read 缩样需 ×1.6 还原），点按一律用 `uiautomator dump` 真值 bounds。
2. **媒体重扫**：`adb shell content call --uri content://media --method scan_volume --arg external_primary`（`MEDIA_SCANNER_SCAN_FILE` 广播在 Android 15 无效）。
3. **非 ASCII 文件名**：`adb push` 会截断（含中文/方括号/空格）→ 先 ASCII 名 push 再设备端 `mv`；验收时 `ls` 核对落盘名。
4. **测量**：`dumpsys gfxinfo` 对已退出进程只回 "No process found"；**绝对 jank% 在模拟器无判定力**（§9.7），只做同条件 A/B；测试结束设备要复原（暗色 + 平衡档）。
5. **读回**：`dumpsys media_session` 用 `state=PlaybackState {…}` 整段正则（裸 `position=` 会串 `buffered position=`）；`dumpsys audio` 按 `sed -n '/- STREAM_MUSIC:/,/^$/p'` 分段取（全篇 grep 会命中事件日志历史值）。
6. **按键**：`adb shell input keyevent` 注不进组合键（`--meta` 不存在）；"键是否被 Compose 吃掉"最快的判据 = 焦点框有没有移动（按键前后各 dump 一次）；冷启动要等 `PLAYING` 再发按键。
7. **录屏/抽帧**：`screenrecord` 遇旋转会中断（产物 moov 缺失）；ffmpeg 输出别用点开头目录；抽帧差分/像素差（`blend=all_mode=difference,signalstats`）用于"两帧是否相同"的客观判定。
8. **UI 断言**：`uiautomator dump` 在"播放中"拿不到快照（窗口永不空闲）→ 先暂停；**对 Popup 断言"面板是否打开"会假阴性**（改用截图字节数双峰）；`focusable` Popup 会吞外部点击。
9. **启动竞态**：慢启动（人为 600ms）是把偶发竞态变必现的最省事手段；修复必须在**同一个慢启动**下复验（E107）。
10. **读 Room 数据**：`run-as <pkg> cat databases/x.db` 只拿到**主库文件**，未 checkpoint 的 **`-wal` 帧看不到**（实测把「指纹没写进去」读成缺陷）。验库要 `exec-out` 同时拉 `x.db` 与 `x.db-wal` 放进同一目录再开；文本抽取用 `grep -a -o -E '键名[a-zA-Z0-9_:.-]*'`（`tr -c '[:print:]'` 经两层 shell 会丢转义）。
11. **主题**：本应用主题显式三态，`cmd uimode night` 对应用无效——切亮色走设置页「主题外观」（平板形态是导航栏的「主题」钮，单击即循环）。
12. **逐像素采样（E118 立的方法）**：验"条底/遮罩是否真的挡住背后"，得先**造一个会透出来的背后**——把一段**纯白**（`b3white.mkv`）或**纯青绿封面**滚到被测条后面，再 `screencap` 拉图用 PIL 逐行取色；底色等于令牌值即"不透"，介于令牌与背后色之间即"透"。同一手法可反推曲线：`alpha = 1 - 采样值/255`，与 `NpMaskFade` 的三段 stop 对得上（实测 y=1520 采到 `(189,188,189)`，与 `startAlpha*0.30=0.258` 的理论值 255×0.742=189 **逐位吻合**）——曲线算得准，判定才敢下。对比度一律用 WCAG 相对亮度式，别用肉眼。
13. **Git Bash 下 adb 的远端路径**：`adb shell screencap -p /sdcard/x.png` 会被 MSYS 改成 `C:/Program Files/Git/sdcard/…` → 整条命令前置 `export MSYS_NO_PATHCONV=1`（它同时影响**本地**目标路径，`/tmp/…` 会落到"当前盘符:\tmp"，所以拉回本地一律写 `D:/tmp/x.png` 这种带盘符的路径，Python 也只认这种）。
14. **重组计数探针（E120 立的方法，替代"读代码猜重组域"）**：在被怀疑的组合体第一行埋 `Log.i("NpProbe", "recompose X")`，`am force-stop` → 起播 → `logcat -c` → 固定 12s → `logcat -d -s NpProbe:I | grep -o "recompose [A-Za-z]*" | sort | uniq -c`。三处一起埋（页面体 / 贵子组件 / 跨进程调用点）就能一次分清"谁在跳、跳到哪一层、有没有真的重挂表面"。**归因用"拔掉法"而不是"加打印"**：把某个订阅改成常量再测一次，掉到 0 就是它驱动的——本轮就是靠这一步发现"局部 @Composable 不是独立重组域"（挪进局部函数仍 41 次/12s，拔掉订阅才 0 次）。**收尾必须反向验功能**：重组归零后要用两张间隔截图做 `ImageChops.difference` 带差分校验，确认被收窄的那块**还在动**——否则"优化"完全可能是把显示优化成了冻结。
15. **深链注入**：`adb shell am start -d "noneplayer://player?uri=…&id=…"` 的 `&` 会被**设备端 shell 当后台符**，参数在第一个 `&` 处被截断（实测把 `id` 整条吃掉，误判成"导航丢了 id"）。正确写法是把整个 `-d '…'` 放进**单引号内再交给一层 shell**：`adb shell "am start -a android.intent.action.VIEW -d 'noneplayer://…&id=…'"`。
16. **DataStore 读键**：`run-as <pkg> sh -c "grep -a -o 'audio_only[a-zA-Z0-9_-]*' files/datastore/*.preferences_pb"` 能直接看键集合；判断"这次有没有写进去"要**前后各读一次对比**，别看文件 mtime（设备时区与主机差 8 小时，容易读成"两小时没动")。
17. **切集耗时的尺子（E123 立，替代"肉眼觉得快"）**：`NpPerf` 打点常驻在装载链上，默认静默，`adb shell setprop log.tag.NpPerf DEBUG` 打开后一次切换出一串 `+Nms`。三个坑：① **首帧只能记在服务侧**——media3 不把 `onRenderedFirstFrame` 转发给 `MediaController`，控制器侧到 `READY` 就到顶了；② `logcat -v epoch` 的第一行是 `--------- beginning of main`，用 `/begin/` 匹配起表点会**命中它**并把 t0 变成 0（实测所有分段都成了"epoch×1000"）；③ `-s TAG1 TAG2` 只认第一个，多标签要写 `TAG1:D TAG2:D '*':S`。
18. **A/B 必须来回装包，且只报绝对计数（E123/E125 各踩一次）**：先跑基线包再跑改动包，两小时的高强度测试会让设备**单向劣化**（实测同一条 1GB 文件的新鲜探测从 1.1s 漂到 2.5–4.3s），把漂移读成回归或把收益读成噪声。做法：**同一台机、同一素材、base→new→base 来回装**，或干脆做一个"把优化用常量关掉"的孪生包（本轮是 `cacheable=false` + 预探测窗口 0）与正式包来回跑，两组数都留在案上。`gfxinfo` 的 `janky%` 与 `p50` 在**帧总数变了**时不可比——降档/去逐帧重组会少产一批廉价帧，剩下的都是真活，中位数反而上升（本轮实测：帧数 238→119 而 p50 从 48ms 涨到 105ms）；只有 `frames / janky / slowUI / slowDraw` 的绝对数可比。
19. **手势与媒体键的注入边界**：`adb shell input keyevent 85`（MEDIA_PAUSE）**能**打到活动会话（`dumpsys media_session` 前后 `PLAYING→PAUSED` 实证），用它把自动连播钉住再测，否则 15s 短片会在测量中途换集、"首帧"计数不再唯一；`media dispatch next` 在该镜像不存在。反过来，`input swipe` **注不进**播放页的竖滑亮度/音量（两台设备、新旧两个包都是 0 次 `setStreamVolume`）——"测不到"不等于"不工作"，这类只能靠代码判据 + `dumpsys audio` 事件日志里的历史证据（本轮就是靠里面留下的 `index:15 oldIndex:15` 同档重发记录，坐实了改动前确实在逐帧打 binder）。
20. **MediaStore 加素材的两条限制**：新目录（`Movies/Big`）不会被应用扫到——扫描是 **SAF 门控**的，adb 造不出授权，想测大文件夹只能往**已授权目录**里 `cp`；`am broadcast MEDIA_SCANNER_SCAN_DIR` 在 Android 10+ 无效，但设备端 `cp` 后 MediaStore 会自己收（等 10s 再 `content query` 复核）。
21. **抓"只存在一两帧"的瞬态错画面（E126 立）**：`uiautomator dump` 单次 ~700ms，**根本抓不到**一帧级的闪回——实测连测 4 次全 0 命中，差点把用户实报的缺陷判成"复现不了"。可行做法是**先起连拍再动手**：后台开一个 `while` 循环 `adb exec-out screencap -p > seq_NR.png`（每帧 ~250ms），循环跑起来之后再去做切换动作，回来比 PNG 体积——空态/稀疏画面比满屏封面网格小一个量级（本案 131KB vs 稳定 723KB），**双峰一眼可辨**，再逐帧目视确认。同一手法可正可反：修复后同序列不再出现异常小帧即为通过。
22. **真机（MIUI）上的两点**：`dumpsys window` 里 `mCurrentFocus=Window{… 弹出式窗口}` 是 MIUI 对 Compose `Popup` 类窗口的叫法，看到它别直接当成应用泄漏（本案那台机器上它属于系统侧，应用当时并未运行）；`adb install -r` 覆盖用户自己装的 debug 包是安全的（同一 debug keystore），但**别碰 `pm clear`**——会连用户的扫描目录授权与播放历史一起清掉。
